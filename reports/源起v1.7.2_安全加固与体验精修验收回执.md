## 2. 阶段二 · 双端存量红点根治与测试门禁

### 2.1 Go 侧：乐观锁根因修复

**失败现象**：`TestCloudAgentCanvasPatchesPersistDraftSubmissionAndAllTerminalStates` 在 `/succeeded` 与 `/failed` 两个子测试中抛 `数据已被更新，请刷新后重试`。

**根因**（非测试噪音）：同一轮推进里，前一次 `repo.MutateCloudAgent` 已把 `revision + 1`，后续写仍带着本轮开始读到的旧 revision，于是撞 `repository.ErrCreationConflict`（`MutateCloudAgent` 的 compare-and-swap 在 `RowsAffected != 1` 时返回该错误）。这正是指令单诊断的「未同步刷新最新 revision」。

**修法**（`backend/internal/app/cloud_agent_runtime_scheduler.go`，`advanceCloudAgentByID`）：冲突时重读最新行重试一次，让「草稿→提交→终态」补丁链在同一轮连续落库；重试仍冲突则原样上抛（调度器 `advanceCloudAgents` 本就按良性冲突处理）。

**验证**：
- 目标测试：`ok yingce/backend/internal/app 9.636s`

## 4. 额外修复的 4 个线上级 bug（非指令单点名项）

### 4.1 电商出图后假错误 toast + `submitImages` 中断（最严重）

- **引入 commit**：`ac0e78fa4`（10-25，commerce 移植收口，把 `useCanvasBatchTable` 换成上游实现）
- **根因**：该 commit 把 `executeBatchGeneration` 结尾从 `return true/return false` 改成无返回，却保留了 `generateConfirmedCommerceRows = Boolean(executeBatchGeneration(...))`
- **用户可见影响**：真实 App 里每次电商出图（确认出图 / 单屏重绘 / 直接生成），任务已成功入队后工作流仍抛「图片任务未提交，请检查模型、素材或任务状态后重试」——**每次生成都看到错误 toast，且 throw 会中断 `submitImages` 的后续状态更新**
- **修法**：`web/src/pages/canvas/use-canvas-batch-table.ts` 恢复布尔返回（+7 行）；兄弟测试 canvas-batch-regeneration / canvas-batch-table-state 10/10 仍绿
- **归因证据**：三重对照（只 stash 战役一 4 文件 / 干净 HEAD worktree 基线 / 失败清单 diff）+ git 历史定位到该 commit

### 4.2 重试定时器被防抖顶掉

`scheduleRemoteUserDataSync` 的失败重试定时器与防抖定时器共用 `syncTimer` 槽，用户一按键就把已排定的 1200ms 租约退避顶掉。修法：新增独立 `syncRetryTimer` 槽位，重试已排定时新编辑随该次重试一起保存。附带修掉一个跨提交回归（节流提交 `1dab360c0` 让保存后重排只拿到 235ms 窗口而非完整 1200ms 防抖）。

### 4.3 `VITE_NXF_BASE_URL` 从未被读取

`vision-client.ts` 把 8823 硬编码成跨域地址，环境变量形同虚设——从 `:3000`/`:8080` 打开直接崩，只有 `127.0.0.1:3000` 能活。已按正确语义修复并补 5 个回归测试锁住。

### 4.4 后端只校验像素不校验字节数

资源上传链路只校验长边与像素上限，20 MiB 以内的 32M 像素大图仍能进推理，把视觉引擎拖死。已在交互文案层按真实口径（20 MiB + 16000 + 32M）修正并纳入错误映射。
