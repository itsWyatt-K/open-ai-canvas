## 一、整体思路：一条「四阶段递进」的主线

本轮更新不是功能堆叠，而是一条**从引擎到契约到界面到门禁**的递进链：

| 阶段 | 主题 | 核心交付 | 本质 |
|---|---|---|---|
| 前置（10-18） | 阶段 4/5 修复 | 派发链三缺陷根治 + 平台驱动三步向导 + 六大 Bug | 把旧电商的「能派发」修扎实 |
| 一期（10-24） | 分层抠图精修 + 批量工坊 | nxf 视觉算子引擎（4 端点）+ L1/L2 双层企划 + 四层交付契约 + 前端三件套 | **开源能力吸收 + 生产关系重构** |
| 二期（10-24~25） | 权重落地 + 通道 B 贯通 | BiRefNet/LaMa 真权重 + Schema 防撞 60→63 + 通道 B 真开关 + AI 换思路接真 LLM | 把一期的「开关」全部打成真开关 |
| 回流（10-25） | 上游合并 | 电商批量逻辑移植进上游 `prepareCanvasBatchTableGeneration` | 本地创新获得上游身份 |

一句话概括：**用开源视觉模型生态替换「AI 烧图」路线，用「透明图层契约」把商品从生成结果中解放出来，用 L1/L2 双层解耦把小白用户和生图机器隔开，用通道 B 把「锁主体合成」从手工精修变成派发级自动管线。**

## 二、架构设计上的决策与取舍（逐项对账）

### 决策 1：视觉算子放 nxf Python 侧车，不放 Go 后端
- **做法**：抠图/重打光/擦除三个算子落在 `nxf/_engine/yingce_bridge/ecommerce_vision.py`（676 行，FastAPI 4 端点），Go 后端与前端均以 HTTP 消费。
- **取舍**：onnxruntime / OpenCV / rembg 的 Python 生态成熟，Go 侧无对等物——**牺牲单体部署的简洁性，换取算子生态与独立升级能力**。代价是跨进程链路（CORS 已开、`VITE_NXF_BASE` 可覆盖基址）与「引擎不在=功能降级」的运行态依赖，因此每个算子都设计了确定性兜底档。

### 决策 2：Provider 抽象 + 权重探测 + 如实降级，拒绝「假装集成」
- **做法**：每个算子一条 provider 链（抠图：BiRefNet/RMBG onnx → rembg → `cv2.GrabCut`；擦除：LaMa → `cv2.TELEA`；重打光：IC-Light 权重位 → Poisson seamlessClone 兜底），权重放到 `nxf/_engine/.models/` 即自动升档，响应体带 `degraded:true + note`。
- **取舍**：GB 级模型权重不硬绑进交付物，**用「档位透明」换「开箱可用」**。一期明言未下载权重、先用 opencv 兜底档（契约全通、测试全绿、质量如实标注）；二期落地 BiRefNet-lite（224MB）与 LaMa big（208MB）后 `config` 报 `degraded:false`。这是全项目最重要的工程纪律：**降级可以，欺骗不行**。

### 决策 3：L1/L2 双层解耦——小白与机器之间砌一堵墙
- **做法**：`EcommerceUserBrief`（L1：主标题≤80/副标题≤120/场景大白话≤600/五枚举版式/锁主体开关）→ `CompileToPrompt()` 自动编译 L2「本屏视觉方案」段；派发时再由 `buildEcommerceSlotPrompt` 拼装 12 段出网。**PromptOverride 铁律**：人工完整覆盖最高优先，L1 重编译只写 `GenerationPrompt`，永不触碰 Override。
- **取舍**：两层各挣各的钱——小白改人话（改 L1 即重编译），机器拿结构化提示词。代价是「同一屏两处真相」的复杂度，用铁律优先级 + 单Writer 字段切割解决。

### 决策 4：四层 layer_manifest 契约先行，数据模型驱动精修台
- **做法**：`EcommerceLayerManifest`（background / shadow / product_cutout + product_rect / text_layers[] / composed）落 slot 最新态 + slot_version 历史态（v60→v63 迁移 +3 列）；前端精修台只是这份契约的可视化编辑器。
- **取舍**：**先契后 UI**——四层清单是对接 PSD 导出、通道 B 自动合成、前端精修台、未来协作评审的共同数据底座。代价是 JSON 契约的版本管理成本（snake_case 双端对齐有测试钉死）。

### 决策 5：通道 B 锁主体合成——「只画场景，不画商品」
- **做法**：`slotWantsChannelB`（L1 显式开启且商品有原图）→ 派发指令注入「【锁主体合成模式】只生成不含商品主体的纯场景承托底图」；`ensureEcommerceProductCutout` 商品级抠图缓存（productID→dataURL，7 屏不重复抠）；`reconcileEcommerceSlotVersions` completed 分支自动 relight-compose → 写 4 层 manifest。**任一步失败静默降级两层，不阻断对账**。
- **取舍**：让 AI 干它擅长的（场景），商品像素 100% 来自原图抠图——根治「商品越生成越歪」的顽疾。代价是多一次抠图 + 一次合成的时延与引擎依赖，用缓存 + 降级两层消化。

### 决策 6：Schema 防撞——为上游让路，给自己留号
- **做法**：发现上游 `CurrentSchemaVersion=60` 与本地 v60（ecommerce_layer_manifest）**同号不同身**，电商迁移改号 **60→63**，59-62 四个空号留给上游 57-60 吸收时顺延；真库 `UPDATE ... WHERE name='ecommerce_layer_manifest'` 幂等修正。悬空合法性：`MigrateSchema` 按 plan 逐条执行（无连续号要求）、`ReadSchemaStatus` 按 MAX 判定。
- **取舍**：**用一次改号 + 四条空号，换未来数十次上游合并的零冲突**。配套 `resolveDataDir()` 环境变量防呆（权威 `CANVAS_BACKEND_DATA_DIR`，旧名兼容告警）——一期「误设旧名导致迁移直落真库」事故的根治。

### 决策 7：AI 换思路——确定性变体器打底，LLM 可选增强
- **做法**：`reworkEcommerceBriefWithHint` 确定性变体器（轮换版式 + hint 融场景，秒级零依赖）先行；`ecommerce_brief_llm.go` env 三元组接入真 LLM（默认反重力 gemini-3.8-flash-high，system prompt 挂载 ecommerce-visual-director 技能规范，严格 JSON 输出校验）；**未配置/超时/坏 JSON 全部静默回退确定性变体器**。
- **取舍**：功能不绑死任何单一模型供应商，**行为确定性优先、智能增强可选**。

### 决策 8：前端大 payload 直连 nxf，不过后端
- **做法**：抠图/重打光/擦除/PSD 导出的 base64 图片由浏览器直连 `:8823`（CORS 已开）；后端只收「四层清单」这种小 JSON（`PUT /slots/:id/layers`）。
- **取舍**：MB 级 dataURL 不过 8080，省带宽与内存；代价是前端要管两个基址（API 走代理、引擎走 `VITE_NXF_BASE`）与双份错误处理。

## 三、借鉴源考证（具体到模块与实现方式）

### 3.1 开源视觉模型生态（一期指令单原文即「开源能力吸收」）

| 借鉴对象 | 借用方式 | 落地形态 |
|---|---|---|
| **BiRefNet-lite（onnx-community 官方 ONNX 转换，hf-mirror 下载）** | 高精抠图主干 | matting 算子 provider=birefnet，CPU 37s/张，中心 254/四角 0 |
| **RMBG / rembg** | 抠图次选 | provider 链第二档，装包即升 |
| **OpenCV GrabCut** | 抠图确定性兜底 | 中心矩形先验 + 闭运算补孔 + 可调羽化 |
| **IC-Light（权重位）** | 重打光的「锁主体光影调和」思想 | 未用 Diffusion 推理，用 **Poisson seamlessClone(NORMAL_CLONE)** 做传统视觉近似：不改商品像素结构，只调和边界光谱 |
| **LaMa big-lama（Carve/LaMa-ONNX）+ IOPaint 策略** | 局部无痕擦除 | mask 包围盒外扩 64px 裁剪 → 等比入窗 512 → 推理 → **仅洞内贴回**（洞外零扰动）；失败回落 TELEA |
| **OpenCV TELEA / Inpaint** | 擦除兜底 | 接口不死 |

另有两个「顺手修出的真 bug」也是深度使用开源栈的副产品：`_load_rgba` 对 data URL 走 `IMREAD_COLOR` 丢 alpha（改 `IMREAD_UNCHANGED`）；distanceTransform 补 pad（实体贴边时图边界也视为 alpha 边界）。

### 3.2 上游 open-ai-canvas（ddcat-ai）——双向关系

1. **画布批量创作表（`prepareCanvasBatchTableGeneration`）**：本地电商的「批量派发/容量看板/顺延补派」逻辑在 `f344a297f` 上游合并时**反哺移植进上游**——本地创新以上游身份回收。
2. **54 号工作台表的确定性 UUID 供料**（`workbench.BuiltinToolID/BuiltinPresetID`）：电商出图按确定性 UUID 取铁律段，同一 key 永远同 ID，跨库稳定。
3. **上游 `/toolbox/image` 56 个电商出图预设**：本地 `/ecommerce`（编排管线）与上游 toolbox（预设直出）**并存不互扰**，统一骑在 M1 生图契约上（`input.negativePrompt` + `referenceImages[].strength/controlMode/maskStorageKey`；声明式插件走 `providerOptions.<iface>.negative_prompt` 原生映射，ComfyUI 走负向节点注入，无负向能力的渠道降级追加禁令段）。商品主图作为 `referenceImages[0]`（role=subject / strength=0.85 / **controlMode=canny**）——复用既有契约而非新造轮子。

### 3.3 nxf 引擎自身
分层 PSD 导出复用 nxf 既有 `/api/nxf/psd/export` 端点（中文图层名，实测 104KB 文件）——**不为四层清单新造导出器**。

## 四、分层结构设计

### 4.1 进程分层（部署视角）

```
web(:3000 Vite)  ──HTTP──▶  backend(:8080 Go/gin)  ──HTTP──▶  nxf(:8823 Python 视觉算子)
       │                            │  │                        │
       │                            │  └─HTTP──▶ 上游模型渠道（即梦/gpt-image/ComfyUI…，M1 契约）
       │                            └─▶ sqlite(.local/data/open_ai_canvas.db) / postgres
       └─────────大 payload 直连 nxf（决策 8）─────────▶
```

**职责切分**：Go 后端是唯一业务真相源（编排/对账/契约）；nxf 是无状态视觉算子集群（三端点全无状态，provider 自动探测）；web 是编排界面 + 精修工作台。三者可独立启停，任一缺失有定义好的降级态。

### 4.2 后端代码分层（模块视角）

```
handler/ecommerce.go（29 条路由，RequireFeature(FeatureEcommerce) 门 + currentUser 鉴权）
        │
app/ecommerce_*.go（编排层，34 文件中的 19 个）
  ├─ ecommerce_orchestrator.go(1428 行)  真实编排器：start/sync/confirm-plan、12 段拼装、nxf 合成与降级
  ├─ ecommerce_brief.go                  L1/L2 双层 + 四层 manifest 契约
  ├─ ecommerce_channel_b.go              通道 B：锁主体指令/抠图缓存/完成端 4 层合成

  platforms.go(6 平台规范字典) / plandetail.go(12 段视觉方案编译器，容错重写)
  plan.go(预设契约) / exitgate.go(S5 视觉安全出口门禁) / sellingpoints.go(三层防御)
```

**关键纪律**：领域层（`internal/ecommerce`）不碰 HTTP 不碰 nxf；编排层（`app/ecommerce_*`）串起领域、nxf、任务系统；Agent 工具与人工界面走同一 service 方法（改稿纪律一致）。派发提示词的三层来源：`PromptOverride`（人工） > L1 重编译的 `GenerationPrompt` > 平台模板兜底。

### 4.3 降级分层（运行视角）——每一层都有「下一层」

| 主路径 | 一级降级 | 兜底 |
|---|---|---|
| nxf 视觉 DNA 合成 | 库内提示词/平台模板直接作正向（degraded 标记） | — |
| 抠图 BiRefNet | rembg | GrabCut 确定性 |
| 擦除 LaMa | TELEA | recreate 无渠道时明确报错不假装 |

| AI 换思路 LLM | 坏 JSON/超时/未配置 → 确定性变体器 | — |

## 五、透明图层架构（专项）

这是本轮最具识别度的设计。**「透明图层」有两个层面：商品主体的透明底（alpha 通道）+ 图层化交付的数据契约。**

### 5.1 四层数据契约（`EcommerceLayerManifest`）

```go
BackgroundLayer string   // 场景背景层（AI 纯场景图，通道 B 下不含商品）
ShadowLayer     string   // 接触阴影层（独立 alpha 层）
ProductCutout   string   // 商品主体层（透明底 RGBA）
ProductRect     [4]float64 // x,y,w,h（0-1 相对坐标）
TextLayers      []EcommerceTextLayer // text/color/font/size/x/y——与烧图文字彻底解耦
ComposedImage   string   // 合成成品（两层降级导出时用）
```

落库双态：slot 最新态 + slot_version 历史态（v63 迁移 +3 列）。文字层用 0-1 相对坐标，分辨率无关——同一份清单可导出到任意画布。

### 5.2 「锁主体铁律」的实现原理（引擎侧）

`relight_compose` 的五步（`ecommerce_vision.py`）：

1. **主体放置**：RGBA 抠图按 scale/xy 落入场景底图（alpha>24 为主体包围盒）；
2. **接触阴影**：按光源反方向偏移生成**椭圆高斯阴影**，单独成层（`shadow_layer_bgra` 带 alpha，暖黑 30,26,22，opacity≤0.8）；
3. **Poisson 融合**：`cv2.seamlessClone(NORMAL_CLONE)` 让商品边缘光谱融入背景——IC-Light 思想的传统视觉近似；
4. **边缘和谐化**（二期增强）：落位环带 LAB 环境色温统计 + alpha 边界内 4px 按距离加权混合 + 环境色 35% 渗色；
5. **锁主体回贴**：`region[patch_alpha > 200] = patch_bgr[patch_alpha > 200]`——**seamlessClone 之后把不透明商品像素原样贴回**，保证商品本体 100% 保真（自测断言：中心漂移 0/255）。

### 5.3 两条产层路径 + 一个导出

- **自动路径（通道 B）**：派发注入「只画纯场景」指令 → 商品级抠图缓存 → 完成端对账时 relight-compose → 自动写 4 层（L1 主副标题转默认 text_layers）；
- **手工路径（精修台）**：一键重抠/框选消除/重打光/文字层增删改，画布实时预览；
- **导出**：合成 PNG（直接下载）+ **分层 PSD**（文字层 canvas 渲染成独立 PNG 图层 → nxf psd/export → 中文图层名，实测 104KB）。

### 5.4 与画布侧通用能力的关系

Cloud Agent 工具链里另有 `image_layer_split`（将图片按对象拆分为独立透明图层，参数同 generate_media 但 mode 固定 image、走独立界面审批）——那是**画布通用**的透明图层拆分；电商四层契约是**业务专用**的图层化交付。两者共享「透明底 + alpha」的同一套视觉语言，但生命周期与审批链完全独立。

### 6.2 状态管理（zustand）

- **`use-ecommerce-store`**（业务 store）：**服务端数据源、本地不持久化业务数据**；`detailById` 缓存 + `refreshDetail` 强制刷新（供编排轮询/对账，绕过 `openProduct` 缓存短路）；**`configSaveChain` 模块级 Promise 串行链**——连续 patch（选模型→切 mode→改比例）必须按提交序落库，否则后写覆盖前写、后端冻结过期配置；派发前必须 `flushConfig()` 等待在途保存；`configDirty` 标记未落库状态。
- **`use-config-store`**：模型口径单一来源——批量矩阵与详情页共用（避免两处口径漂移）。
- **`stores/canvas/use-ecommerce-store`**：维护「电商工作台」画布 ID（Agent 运行时硬绑定真实画布）。
- 对话框内部状态（manifest 草稿/框选 rect/光源选择）全部 `useState` 局部化，不进全局——精修是重状态操作，但生命周期随对话框。

### 6.3 样式体系

**antd 6（组件底座）+ Tailwind 4（原子类）+ CSS 变量主题 + 模块作用域私有类**四层混搭：
- 主题 token：`var(--border)` / `var(--surface)` / `var(--r-lg)` / `--foreground/45` 透明度系，`color-mix(in srgb, var(--surface) 82%, transparent)` 做毛色底层；
- 状态语义色板集中定义：`CELL_TONE`（矩阵：completed 绿 / failed 红 / running 紫 / queued 灰 / uncertain 琥珀）与 `SLOT_STATUS_TONE`（屏卡同色系）——**同一状态全界面同色**；
- `.ecommerce-*` 模块类只放布局骨架（shell/main/header），视觉细节一律 Tailwind；
- 图标 lucide-react，按语义选型（Scissors 抠图 / Eraser 消除 / Lightbulb 打光 / Type 文字 / Layers 图层）。

### 6.4 交互流程（主链路 + 两条专线）

```
导入商品（三段式上传：预留→分块→合并）
  → 平台选择 apply-platform（6 平台字典自动注入策划 Prompt 与槽位基底）
  → AI 策划 plan（12 段视觉方案，先审方案门禁）
  → confirm-plan 批量/单屏派发（容量看板：平台在途上限、失败重试、顺延补派）
  → 对账（GET /products/:id 详情即对账，屏级状态最新）
  → 图层精修（已出图屏出现「图层精修」入口）→ 导出 PNG/PSD/ZIP/长图
专线 A：批量企划矩阵（≤25 商品 × 屏序，异常标红拦截 → 批量 confirm-plan）
专线 B：L1 企划卡（失焦自动保存→后端重编译 L2；✨AI 换个思路回车即换；
        🔧 底层 L2 默认折叠——小白永远不见 Prompt）
```

细节纪律：L1 输入 `maxLength` 前端预检 + 后端 `Validate()` 双保险；「先审方案」checkpoint 后的人工修改不被重新合成覆盖（stage 提示词兜底 + Override 优先级）；失败屏直接展示 `errorMessage` 不再假装排队。

### 6.5 前后端数据交互

- **REST 主通道**：`/api/ecommerce/*` 29 条路由（config/presets CRUD、products 增删查、start/sync/confirm-plan/apply-platform/pause/plan/apply-plan/retry/duplicate、slots 的 prompt/brief/layers 三 PUT + regenerate、export/export.zip/plan-response），统一 `RequireFeature` 门 + `currentUser` 属主校验；
- **进度通道**：`waitForEcommerceProduct` 轮询详情（详情即对账，无需独立进度端点的设计）；
- **引擎直连**：精修台四个 nxf 端点 + PSD 导出走 `VITE_NXF_BASE`（默认 127.0.0.1:8823），dataURL 大 payload 浏览器直传；
- **资源通道**：图片统一 `/api/resources/:id/file`；精修台 `urlToDataUrl` 把资源 URL 转 dataURL 喂引擎；
- **Agent 上下文双通道**：`references`（商品实拍原图，视觉模型直接看图）+ `prefillRequest`（结构化文本：商品 ID/名称/平台/卖点/各屏文案，`requiresVision:true` 走视觉路由；延迟 120ms 递增 nonce 修复挂载时序预填丢失）；
- **契约类型化**：`services/api/ecommerce.ts` 是前后端契约的 TS 镜像（snake_case JSON ↔ TS 字段），四层 manifest 的往返有单测钉死。

## 七、质量门禁与已知边界（如实）

**门禁**：nxf 算子自测 8/8（含锁主体中心漂移 0/255、边缘和谐化 G 通道 30→60 环境渗色）；Go 分片门禁 S1-电商 15 pass / S4 渠道 139 pass / 0 fail；model-adapt 21/21；前端 tsc 0 错误；真机 E2E 跑通登录→上传→抠图（birefnet degraded=false）→L1→AI 换思路（真 LLM 7.9s）→锁主体派发（模型两次真实出图）。

**已知边界**：① E2E 尾步被上游 CDN 结果文件下载阻塞（多日存量问题，与本期无关，建议配 `proxy_url` 或网络窗口手动 `recover-media`）；② IC-Light Diffusion 权重位保留（relight 现有 Poisson + 环境色温 + 羽化增强，可用）；③ recreate 局部重绘需生图渠道（引擎明确指引走画布，不假装）；④ 批量矩阵上限 25 商品/轮。
