# 角色母板、依赖与角色设定板

## 0. 路线分流

- A完整资产：执行本文件全部生成、回传、逐批验收和依赖解锁规则；提示词只在内部用于直接生图，默认不展示，创作者主动索要时才输出。
- B只输出提示词：仍先确认角色清单，再按依赖层从上游到下游逐批输出9:16母板与16:9设定板提示词；每批确认后才进入下一批，不调用生图，不要求回传图片。依赖提示词以`{{Image 1}}`声明外部平台应绑定的上游资产，提示词确认只冻结设计，不把图片状态写为已确认。
- C直接视频：不进入角色图片资产流程；角色与状态只进入4类资产范围表，由用户标记已有可用、自行补充、文字承担或删除。后续视频批次根据用户处理方式安排上传映射或文字身份锚点，不识别或核验本地文件。

下文未特别说明的“必须确认图片后解锁”只约束A路线。B按提示词批次解锁；C不进入角色图片生产门禁。

## 1. 先建立依赖图

以创作者确认的剧本解析与人物小传为上游真相，提取全部出场人物、生物、怪物及被提及但影响视觉设计的实体。为每个实体登记：年龄、国籍/族裔、身份职业、人物弧、外貌、体型、服装、道具、状态变化和依赖。不得在角色提示词阶段重新发明国家、年代、职业或家庭关系。

以下关系必须有向依赖：血缘亲属；同一人的换装、年龄、受伤和变异；双胞胎/克隆；宿主与变身形态；绑定装甲/生物；连续破损状态。A路线中，有上游依赖者只输出等待卡，上游图片确认前不得生成下游；B提示词路线在上游提示词批次确认后可输出下游提示词，但必须在首句声明外部平台的上游图片占位符与唯一职责。C只把依赖关系写入资产范围和文字连续性。

依赖层必须通用化判断，而非按剧本称谓写死。典型顺序是“独立/父母/原始人形→子女或其他血亲→变异/受伤/换装/年龄状态”。如果某个子女的外貌同时依赖2名父母，两名父母都确认后才解锁；如果变异形态依赖人类原形，原形确认后才解锁。

依赖图完成后，先按`workflow.md`展示角色立项表，列出全部角色与确有视觉价值的状态、上游依赖、建议批次、必要性和出图理由。A路线不得在清单确认前生成第1批图片；B路线不得在清单确认前输出第1批提示词。也不得把一次性表情、轻微污渍或普通动作拆成独立状态图。创作者可删除过度拆分项，或把仍需但暂不生成的项目标为`待外部补全`。

## 2. 第一阶段：9:16单人确认稿

同一批次一次处理全部同层无依赖角色。A路线在内部按下方结构编译提示词并直接批量生成图片，回复只展示图片与资产标识，不展示提示词；创作者主动索要时才交付对应提示词。B路线只输出当前已解锁批次的全部提示词，确认后才继续下一依赖层，不调用生图或等待图片回传。创作者要求修改时只重编受影响角色；A路线按需重生。A路线未确认图片状态保持`候选`或`待修改`；B路线把提示词状态与图片状态分开记录。每个提示词按以下结构，字段没有内容时删除，不留空标签：

```text
【版式】单人全身立绘（角色确认稿），正面面对镜头，站立姿势。
【画质与风格】[继承全片写实风格核心与材质；真人实景拍摄质感，杜绝游戏CG感和精修滤镜]
【骨相锁定】（最高优先级）[按剧本种族与地域明确眉弓、眼窝、鼻梁、下颌、颧骨；同步禁止相冲突骨相]
【命运气质】[年龄＋职业/命运形成的气质，排除偶像感]
【五官】[脸型、眉、眼、鼻、唇逐项可见描述]
【皮肤】[肤色、风霜、毛孔、细纹、伤疤]
【发型】[颜色、长度、形态、质地]
【体态】[身高、骨架、肌肉/脂肪、站姿与重心]
【服装】[逐件写款式、颜色、材质、磨损、污渍、左右锚点]
【道具】[反复出现或身份关键的佩戴/手持物]
【细节】[最能体现身份的一处面部或肢体细节]
【姿态与表情】无表情，面部肌肉放松，双手自然下垂。
【背景与光影】简单干净的浅灰背景，柔和均匀中性影棚光，无色偏，无杂物。
【严格禁止】[角色定制禁令＋换脸、混血误判、精修、崭新戏服、时代错位]
【核心气质】[一句话灵魂总结]
【画幅】9:16竖幅，4K高清，全身镜头，完整展示脚部。
```

提示词应具体、千人千面。禁止只写“帅气、电影感、高级、普通身材”等模糊词。

## 3. 依赖解锁

- 亲属角色引用上游定稿图，只继承2至4项稳定家族特征，并按年龄、性别和经历自然分化；必须“像血亲但不是同一张脸”。
- 同一人物的换装、受伤、年龄和变异最大限度保持原脸、身高和骨架，只改变剧情明确部分。
- 双胞胎或克隆体才允许高度相似复制。
- 用户上传图片不等于定稿；A路线必须获得明确确认后才能作为视觉真相解锁下游。C路线用户声明已有只代表未来可能上传，不触发图片验收。
- A路线在上游角色整批图片确认后才生成下游角色；B路线在上游提示词整批确认后即可输出下游提示词，但必须保留外部生成顺序和占位符职责。
- A的依赖角色只能由`已确认`视觉上游解锁；`待外部补全`不等于确认。B的下游只由上游提示词批次确认解锁，提示词确认不等于图片确认。C的`自行补充`不阻塞导演地图或视频提示词，只在本批上传映射中标为待用户准备。

## 4. 变异程度门禁

剧本未明确时只询问1次：H1人类主导（80%至90%保持人类，局部牙齿、眼睛、指甲、手脚、耳部或体表异化）；H2均衡混合；H3野兽主导/完全兽化。剧本已经明确则直接锁定并说明依据，不重复询问。

每个变异阶段独立登记，不能用最终形态污染早期形态。

## 5. 第二阶段：16:9角色设定板

A路线只有在角色9:16确认稿明确确认后，才生成角色设定板，并在内部编译下方提示词直接生图，不默认展示提示词。B提示词路线在9:16提示词批次确认后即可交付对应设定板提示词，并明确`{{Image 1}}`应绑定用户在外部平台生成并选定的该角色9:16图；此占位符不代表图片已经上传或确认。`{{Image 1}}`始终只负责该角色身份与当前造型；除非创作者确实存在第二张参考，不得虚构`{{Image 2}}`。设定板不再默认生成侧视图，而以“正面无头服装视图＋背面完整视图＋面部特写”提高身份、服装与发型的有效信息密度。A确认生成结果，B确认提示词设计；C不生成角色设定板，直接使用资产范围处置。

先判断左上信息语言：剧本规范姓名为中文时，使用中文姓名、`身高`、`性格`；规范姓名为英文或拉丁字母时，使用原文拼写、`Height`、`Character`；同时存在音译名与原文名时，以创作者确认的规范原文名为准。只有角色称谓而没有姓名时，原样使用剧本称谓及其语言。信息字段只由规范姓名、身高和性格组成，且语言统一。

```text

画面为16:9横构图、极简浅灰白无缝影棚背景。左侧约46%区域由上方紧凑人物信息和下方2个全身视图组成；右侧约54%区域为面部高清特写。左上信息区总高度不得超过画面15%，人物姓名字号约占画面高度4%，下方设置[身高/Height]和[性格/Character]两行小字，字号约占画面高度1.6%。信息区不得挤压或覆盖人物视图。

左侧2个全身视图从画面约18%高度处开始，占画面高度约76%，等比例、底部对齐并完整展示到脚底。第1个是严格正面的服装与身体视图：从颈根开始，完全不显示头部、脸和发型，不得出现空白脸、模糊脸或遮罩脸；双臂自然下垂。第2个是严格背面完整视图：必须保留完整头部和全部发型，尤其清楚展示长发、盘发或后脑发型结构；只能看见背面，严禁露出侧脸。2个视图必须是同一人物、同一体型、同一服装和同一比例，双手、腿部、脚部完整，鞋底或脚底接触地面。

右侧为同一人物从头顶到衣领及少量肩部的面部特写，正面微侧，五官身份与 {{Image 1}} 精确一致，不改变脸型、年龄、皮肤纹理、发际线和发型。

使用大面积柔和中性影棚光，全部区域光线方向一致，人物脚下仅有轻微自然接触阴影。皮肤、鼻头、额头、嘴唇、头发、服装、金属配件和鞋面全部压低尖锐镜面反光与油亮高光，呈真实自然的哑光材质；眼睛保留极小、柔和的眼神光，金属只保留非常弱的小面积柔光反射。严格保持 {{Image 1}} 的原始肤色、服装固有色与自然明暗关系。

3个视图中的人物身份、年龄、体型、发型、服装层级、鞋袜或赤足状态、配件、道具、伤疤、纹身、破损及毛发状态均与 {{Image 1}} 完全一致，左右非对称锚点保持原方向。背景保持干净，除左上规定人物信息外不生成其他标签、箭头、尺寸线或水印。8K超高清，16:9横构图。
```

## 6. 验收

A逐张检查：同一人、正确年龄骨相、正面视图无头且不留假脸、背面视图保留完整头部发型、完整脚部、服装层级、左右锚点、道具、变异阶段、信息字段与字号、哑光高光、原始固有色。确认后登记永久ID；失败只修正失败字段，不重新选角。B只检查当前批次提示词是否覆盖同样的可见验收标准，并把结果记录为“提示词已确认”，不得登记成视觉资产已确认。
