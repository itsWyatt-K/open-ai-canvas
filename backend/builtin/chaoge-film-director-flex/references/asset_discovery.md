# A/B/C路线实际资产发现与确认

## 1. 定位

本规则是三条路线进入视频阶段前的共同门禁：A完成完整资产制作后使用，B完成全部资产提示词后使用，C在P0S定风格前先用来预检素材，并实际查看风格依据；P0A后核对人物对应，P1后P2S只补变化与未确认项。A继续用完整台账管理上游制作，B继续记录提示词进度，但二者都不能用记录状态代替实际文件扫描。

A/B/C进入视频制作前，不再让AI从剧本推测一套“用户可能拥有的资产表”，也不得把A台账中的文件说明或B已经确认的提示词当作当前可上传文件。实际文件与用户当轮上传项才是可映射资产的事实来源；剧本解析只用于判断这些文件可能对应谁、哪个场景或哪种声音，不得把推测写成已经存在。

## 2. 资产根目录定位

先读取用户指定项目和已登记素材根目录，一次扫描该项目范围内全部图片、音频和视频，包含 `00_最终确认资产`、项目其他素材目录及用户明确指定的补充目录，不只扫描当前片段或最终目录中的图片。范围已经明确时直接扫描，不逐目录询问；不扩展到整盘或无关项目。跨目录重复文件合并显示来源，历史候选标明状态，不将全部扫描结果直接变成上传队列；最终采用目录中的当前版本优先按真实确认依据识别。项目外工作目录只有已登记为本项目素材来源或用户明确指定时才纳入。

未建立最终交付目录的旧项目或C路线，按以下顺序只读定位一个项目资产根目录：

1. 创作者明确指定的资产文件夹；
2. 剧本同级的`<剧本文件名去扩展名>_资产`；
3. 剧本同级名称同时包含项目名与`资产`或`assets`的文件夹；
4. 当前项目文件夹中明确命名为`资产`或`assets`的文件夹。

不得递归扫描整个磁盘、用户主目录或无关工作区。已知项目根目录可直接扫描；只有项目及素材范围均不明确时才集中询问路径或上传，不猜测无关目录。

推荐子目录及兼容别名：

- 人物：`01_人物`、`01_角色`、`人物`、`角色`、`characters`、`cast`；
- 道具：`02_道具`、`道具`、`props`；
- 场景：`03_场景`、`场景`、`locations`、`scenes`；
- 声音：`04_声音`、`04_音频`、`声音`、`音频`、`audio`、`voices`；
- 站位/连续性参考：`05_站位参考`、`站位参考`、`continuity`、`handoff`。

可运行只读扫描器：

```text
python -X utf8 scripts/scan_project_assets.py "<项目资产根目录>"
python -X utf8 scripts/scan_project_assets.py "<项目资产根目录>" --json
```

## 3. 扫描结果不是自动验收

扫描只证明“发现了某个文件”，不证明角色身份、版本、画面质量或声音内容正确。AI必须把项目全量扫描结果和创作者当轮上传项合并为一张紧凑表，包含所有图片、音频、视频，不按开场人物或媒体类别分轮提问。可分组显示但同轮完整交付，用一组编号确认整批身份/采用建议，修改项集中处理；声源身份建议也包含在这轮确认中。在表后按sound_and_music.md的角色优先级给一次干声提示：已找到、部分找到或完全没有都说明采用参考与模型生成的分工；主角/重要常驻角色只作可选建议，路人无需专门准备，不另问是否补交或是否跳过。凡是本地文件，`本地资产`列必须写成Codex可点击的绝对路径Markdown链接；不得只显示不可点击的文件名，也不得在表内直接嵌入大图：

| 序号 | 类别 | 本地资产/上传项 | AI识别建议 | 用户确认 |
|---|---|---|---|---|

执行规则：

- 人物按P0A已知的主人公→次主角→配角排序；同一人物的基础形态在前、状态变体在后。
- 场景按主场景→次场景排序；声音按主人公→次主角→配角排序；道具按因果重要度排序。
- 文件名足够明确时可给`AI识别建议`，但必须标为建议；文件名含糊时读取图片内容或可用元数据后给建议，仍由用户最终确认。
- 声音文件只根据文件名、时长和创作者说明识别；没有可靠证据时写`待用户指认`，不得臆测说话者。
- 用户直接上传的图片、音频或视频也进入同一张表，来源写`本次聊天上传`。
- 本地图片写为`[预览：文件名](<C:/绝对路径/文件名.png>)`，本地音频写为`[播放：文件名](<C:/绝对路径/文件名.wav>)`，本地视频写为`[预览：文件名](<C:/绝对路径/文件名.mp4>)`。路径必须是绝对路径；含空格或中文时使用尖括号包裹链接目标。
- 表格必须直接输出为Markdown，不得放入代码块，否则链接无法点击。
- P3A不重复内嵌这些原始资产图，原始文件通过此表点击预览；P3A先确认文字提案的原文范围与安排，再按proposal_storyboard.md生成一次宫格草图并展示问题，确认含已展示首镜，P3B只核对依据并准备必要新增输入图。
- 序号在本次确认前可调整；确认后作为当前实际资产快照冻结。增删、替换或同路径文件元数据变化时重扫；只更新变化项及其依赖，不重问未变资产身份。

全量表后直接逐行展示“1｜采用本表全部图片、音频、视频的身份及版本建议；2｜调整，说明素材名称及对应修改”，不再分别确认图片与声音。表中仍有未知身份时，把待指认项及实际候选集中列清；不能把选1解释成已确认空白身份。

### 人物采用筛选

扫描器展示的是发现清单，历史图片仍可出现，不能把全目录直接变成上传队列。人物按character_assets.md 0.2节合并同角色状态：对外上传表只列当前已确认信息版，竖版/被替代版作为留档说明，不分配最终图号。已有确认依据沿用，不重复要求确认所有人物；缺少采用关系时仅询问冲突项。C沿用实际资产识别，不擅自新增整套人物制作。

LibTV当前绑定的每张图片必须记录`category`（人物/道具/场景/站位参考/其他）；人物额外记录`file_role`、`adoption_status`与`confirmation_source`，由实际图片和确认记录填写。未知身份不能用“其他”逃避指认；旧记录只补齐有证据的字段。`workflow_state.py`检查当前视频绑定中的角色信息版采用条件，文字规则还适用于CLI手工执行/节点复用。脚本不能代替实际看图，也不能凭文件名认定用户确认。

## 4. 无文件时的友好提示

本节仅适用于项目内全部可用映射素材都未发现；仅缺干声（包括零干声）不进入本节，按第3节提示后继续正常流程。全无文件时使用以下短提示确认视觉是否由文字承担，不输出AI臆测清单；用户已明确纯文字生成则直接沿用：

```text
我还没有在[资产根目录]发现可用于视频映射的人物、道具、场景或声音文件。
1｜提供已有素材：直接上传，或将文件放入项目目录后回复“重新扫描”（也可给出新的素材完整路径）。
2｜本项目采用纯文字生成，不绑定文件素材。
回复1或2，也可直接上传/提供路径；选1后须等实际素材到达再识别，声音参考无需专门补齐。
```

扫描中的BGM、音效或身份不明音频不能自动算作已确认角色干声；已有干声也只按当前实际采用范围绑定。声音准备建议不是视觉资产缺口，不能将提示过的重要角色变成必须补齐项。按sound_and_music.md保留原文人声并随视频生成。实际音频身份不明时集中列待指认，未确认不绑定；不要求逐个回答、强制上传或单独生成。

## 5. 三路线共用视频入口

- **A路线**：保留完整资产台账及按asset_review.md执行的验收依据；准备进入视频时进入本规则，扫描当前项目实际文件并让创作者确认“目前视频阶段可用资产是否准确”。assets_only不主动触发视频入口。台账条目没有对应实际文件时不得映射。
- **B路线**：角色、道具、场景提示词的分批输出和确认完全保留。最后一个资产提示词批次确认后，不假定外部图片已经生成；进入本规则，扫描实际文件并让创作者确认实际身份与已列明缺口的处置。
- **C路线**：P1确认后直接进入本规则；取消从剧本自动提取人物、道具、场景、声音4张建议表。实际文件或当轮上传项确认后进入P2V。
- 三条路线都不计算哈希、不宣称扫描文件已通过画质验收。A把快照写入完整台账的视频入口栏目，B/C把快照写入轻量状态；共同保存根目录、相对路径/上传来源、类别、用户指认和确认时间。
- 恢复项目或资产目录发生变化时，进入下一个视频单元前重新扫描一次；结果未变化时只显示一句`实际资产快照无变化`，不重复整表确认。
- A/B/C后续P5【本批上传ID映射】的`用户应上传的资产`列必须复用同一份本地文件的可点击绝对路径链接；不得退回纯文件名或仅引用A台账ID。

## 6. 进入P2V的通过条件

视觉素材满足以下任一条件才可以进入P2V：

1. 创作者确认扫描/上传得到的实际资产快照及身份准确；AI已核对当前需求并列明缺口与后续准备项；
2. 创作者确认快照不完整，但明确哪些视觉素材稍后自行补充、哪些由文字承担或不用于视频；
3. 创作者明确选择本项目纯文字生成。

声音方式由AI记录`reference_or_generated`；当前或未来没有声音参考都不阻塞P2V、提案和生成。required_voices保留剧情人声需求；已绑定音频仍须实际存在且身份确认，无参考则随视频生成，不凭空建立音频槽位。

不得因为AI从剧本推测出“还应该有某项资产”就擅自添加资产或分配图号。需求与缺口由AI核对，用户只确认实际素材身份、采用版本及明确缺口的处置，不让用户凭空判断全片素材是否专业完整。展示实际表后用编号提供“确认这批素材及所列处置／修改身份或补充素材”等本轮适用选项；不混用表内资产序号与操作序号。进入具体视频单元后仍按`dynamic_asset_gate.md`检查实际需求，未来缺口不自动阻塞当前单元。

扫描记录增加size_bytes与modified_ns，供变化提示而非画质验收；它们不能证明文件内容相同，用户明确说明替换时即使元数据未变也更新revision。当前用于映射的文件交付前检查存在；上传项用upload:来源标识。资产稳定ID与revision用于依赖，scan_id或本批图号不作为永久身份。

## 风格预检的额外职责

扫描器只发现文件，不会自动看图或证明风格一致。按 `references/style_entry.md` 实际查看决定风格的素材，并记录媒介、采用/参考职责、是否可读及冲突。先观察、后结合剧本指认；重复文件与历史候选不参与数量投票。全片global_style与局部look_only、身份identity、空间spatial、动态motion分别登记。已有有效身份不反复询问。
