# 视频执行方式：不接入与LibTV CLI

本文件只决定谁操作视频平台，不改变A/B/C资产路线、导演方案、首帧确认、声音规则或提示词格式。阶段与展示规则仍以 `references/workflow.md` 为准；选LibTV平台不等于授权CLI，场景出图使用CLI也不自动决定视频执行方式。

## 入口选择与恢复

P2V平台未知或要求重选时，先按workflow.md展示三个平台，LibTV选项注明可接入CLI或不接入。只有选LibTV才有下面的CLI分支：选择LibTV且执行方式未定后，下一条回复立即在模型问题之前完整展示，不合并其他设置：

**已选择LibTV，是否接入CLI？**

> 1｜接入LibTV CLI，由我上传素材、生成并下载视频。
> 2｜不接入，按原流程交付素材顺序、平台设置和完整提示词，由你操作平台生成。

回复1或2即可。选择后再按workflow.md展示下一项模型/画幅/分辨率的实际编号菜单。选择即梦或其他平台不展示上述问题，按手动提示词流程记录manual，来源为本次平台选择及对应流程；从LibTV切换时不沿用旧CLI授权，不扩展为新平台的自动操作。

已有明确选择直接沿用。“用LibTV平台”本身不足以选1；用户明确要求由AI在LibTV实际出视频、自动上传并运行，属于CLI执行授权，不重复询问。同一项目已确认的方式不逐段重问。未答时保留pending，等待这一项选择，不先转问模型；可做内部独立准备，不能跳过可见选择。用户明确要求暂缓接口选择、先做独立提案或提示词时从其要求，不以等待超时推定同意连接。

在现有execution中记录可选的video_execution对象：mode为pending/manual/cli，selection_source为真实选择依据。新项目由pending开始；旧记录没有该字段时保留原手动交付能力，不据此推定CLI授权。用户后来明确不接入则改manual，取消尚未提交的自动运行待办；已提交任务先查询并说明实际状态，不虚构撤销成功。仅切换执行通道不重做已确认资产/提案/首帧，也不自动更换平台或模型。

## 两条路线共有的创作前置

每段先按workflow.md展示文字AI导演提案，确认原文结束位置与逐镜简述，再按 `references/proposal_storyboard.md` 一次生成并展示实际宫格草图、列出问题，短标签讲每镜怎么表演、怎么切；记录用户或授权代理对具体版本的决定。指定镜号只改对应格并复查衔接，确认覆盖已展示首镜，P3B沿用首镜依据；新增平台输入图另行展示确认，再内部编译素材映射、生成设置和完整视频提示词。代理不得只把文件路径、采用摘要或后台任务消息当作提案展示。CLI保留提案及图像确认；提示词默认内部使用，不要求可见交词或再次确认提示词。写入台账不能冒充提案或图像已展示。

提示词中的LibTV占位符仍由platform决定；video_execution.mode不改变占位符语法。不接入时的上传表是给用户的操作计划，接入时实际上传后才报告已连接的素材；二者均只能引用已有且已指认的实际素材。

## manual：保持原流程

- 操作平台仍由用户负责；导演创作统一执行宫格提案流程；下一步明确“按表中顺序上传素材，设置本段参数，复制完整提示词生成；需要验片或修复时提供结果”。用户只要求继续提示词时可继续下一单元，不把未回传视频写成已采用事实。
- 不因选择LibTV而安装CLI、登录账号、绑定画布、自动上传或创建收费节点；本地导演与提示词交付不以CLI状态、远端节点ID或任务回执为前置。
- P2S现有素材身份确认、角色声音要求及首帧门禁仍适用。不接入CLI不等于B资产提示词路线，不要求重选A/B/C，也不删减上游资产、3D、风格参考或导演步骤。

## cli：内部编译后直接执行，提示词按需展示

- 默认不在聊天粘贴完整提示词，也不默认发送提示词文件链接、附件或折叠块。内部保留上传映射、外置生成信息与完整提示词供校验，实际提交只取正式提示词正文；不得为了不展示而跳过校验。用户索要时展示当前实际版本，不额外生成一版，也不因查看而重复提交。
- 首版和返工均按当前执行方式交付；CLI已授权但连接失败时说明实际问题，不悄悄改为手动交词。旧版已经交过提示词的当前段沿用有效确认，先查是否已提交，未提交才执行，已提交只查询原任务。
- 仅此模式读取 `references/scene_execution.md` 第2节复用当前官方CLI检查、实际登录状态、专用画布身份和绑定方法。已可用的连接沿用；无连接时在执行前解决，不阻塞独立创作工作。CLI参数从实际帮助/schema取得，不硬编码测试账号、路径、画布或旧API凭据。
- 当前方案、首镜依据及必要新增输入图已确认，完整提示词已内部编译校验且相关授权有效后，上传/复用真实素材，核对图音视频各自顺序、实际连接、模型、时长、画幅、分辨率和声音设置，再运行。执行授权已存在时说明下一动作后直接执行，不再索要同一许可。连接失败或结果不明时说明卡点，先查询同节点，不直接重复提交。
- 取得任务回执、下载实际视频后，检查时长、实际像素/画幅、声音轨及内容；分别报告技术检测、可见画面和实际听音覆盖。请求档位不等于输出规格通过，脚本/ASR不替代画面或听音验收。
- 展示实际结果、采用/修改方式及下一动作。采用后按实际结束状态继续下一段提案；失败时说明最小修复或可选的手动交付方式，不静默改变执行路线。

## 本轮交付前的路线核对

CLI连接成功后回到本轮尚未完成的素材或导演步骤，不额外询问用户自行决定剧情起止。已确认参数继续使用，用户明确要求重新确认时按workflow.md的重测范围处理。“下一步”按当前产物与任务状态解析：内部编译通过后直接执行当前段、运行中查询原任务、实际视频采用后再推进；用户明确只要下一段提示词时仅推进创作，不伪造前段采用。

先区分“平台=LibTV，用户自己操作”与“用户授权AI自动运行”；再检查当前聊天是否已展示并确认本段文字提案、宫格（含首镜）及必要新增输入图；manual还须可见交付完整提示词，CLI只须内部编译校验并记录真实提交状态，结尾指出当前方式下的真实下一步。代码只校验执行方式字段与选择依据，不能证明这些内容在聊天中实际展示或被人看见。

## 其他功能的不接入边界

不接入CLI限制对应平台的自动操作，不取消已授权的本地处理或当前窗口创作，也不自动把A改成B。用户明确的是仅视频、不接入某平台或本项目全部不接入时，分别记录适用范围；已有选择不逐功能重问。手动外部生成不以浏览器、另一连接器或换平台绕过用户决定。

| 功能 | 不接入时的交付 | 实际回传边界 |
|---|---|---|
| 用户视频配乐 | 读取视频后直接给完整BGM提示词、必要设置与下一步，按post_music.md | 合成时需实际音乐，提示词完成不等回传 |
| 视频生成/返工 | 完整当前提示词及必要素材/参数；修改稿依原规则精简交付，画面设计变化先更新相关宫格 | 验片、抽帧或剪辑需视频，只继续提示词不强制回传 |
| 外部图片生成/修图 | 已选手动出图时给完整提示词、真实参考顺序及设置；已授权Codex生图按原流程执行 | 依实际图片修图/归档才需图片；B提示词可独立完成 |
| 独立补音效 | 外部手动生成时给声源、动作、材质、空间、尾音的完整提示词；对位/增益放外部说明，不夹带音乐 | 混入视频需实际音效；原音轨修复不必先生成新音效 |
| 显式请求360度补角 | 给已确认首帧、入口设置、完整补角提示词与手动说明 | 收到视频才能验收、抽帧，不能拿提示词冒充补角结果 |
| 本地剪辑、抽帧、原声精修、已有音乐混音 | 有实际媒体且已授权就用本地工具处理并交文件，不要求CLI或远端回执 | 缺哪份必要媒体才补哪份；工具不可用时如实交操作说明 |

3D、宫格提案、首镜依据、风格参考询问和下一步引导继续保留。manual下远端任务ID、登录、上传连线和下载回执不作为提示词完成条件。本地处理完成、提示词已交付、外部媒体待回传与最终媒体已采用分别记录。

## 真人参考的官方关联与下载规格

LibTV真人素材若需平台校验/人像关联，使用当前官方流程及真实返回的记录。复用已上传人物时，先核对同一节点、文件/URL、版本和职责；平台已给出的portraitAssetId及列表中的assetId等关联元数据应随实际素材保留，不能只重建图号/URL而丢失绑定。mixedList、imageList及各自顺序须与实际输入一致。不得为过审编造assetId、豁免标记或关闭审核；局部模糊信息版不是审核许可。

参考图被拒时记录原任务及平台原话，区分是否尚需官方校验，不猜词或换语言试探；状态变化先重新读取原节点，避免把已成功任务当成仍失败。没有可用官方入口或仍被拒时说明实际卡点，不反复付费重试。

下载按当前CLI帮助使用官方去水印选项；需要会员声明时先读当前有效会员状态，不能虚报会员。请求720P等档位不等于实际像素达标；下载后检查实际尺寸，若另交放大版，保留原片并说明放大，不冒称原生输出。母带仅处理声音时优先复制视频流，不借此改尺寸、帧率或画面。
