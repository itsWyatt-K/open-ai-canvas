# 路线先行与看样片定风格

## 新项目入口

本文件管P0R/P0S入口，P1细化见 `references/style_lock.md`。顺序固定为：接收定稿并内部通读 → P0R明确A/B/C → P0S按路线读取参考并确认风格 → P0A十项分析及情绪曲线 → P1细化创作基准 → A/B资产制作或C复用素材 → P2S核对实际素材 → 视频流程。通读不等于提前展示十项分析；已有明确路线或风格只核对实际依据，不重复提问。用户明确要求只解析剧本等局部任务时遵守其范围，不强制补齐完整生产入口。

P0收到剧本后简短说明已接收。路线未知就在正文列出：

1｜A 完整资产制作：我制作人物、道具和场景图片。
2｜B 资产提示词协作：我交提示词，你在外部生成资产。
3｜C 使用已有素材：先读取已有素材，再制作视频。

用户明确回答后才进入本路线的风格步骤，不在同一回复堆叠下一轮风格选择菜单。路线是默认分工，允许局部复用/补做，不另开第四条路线。A/B也须先看用户明确要沿用的已有资产，避免风格锁定后才发现冲突。

## A/B样片选择页

读取 `assets/style-presets/catalog.json` 与 `references/style_presets.md`。本版仅六个内置风格，顺序固定：

1｜真人影视风
2｜真人短剧风
3｜CG写实虚幻风
4｜3D皮克斯画风
5｜3渲2厚涂风
6｜2D国漫水墨风

运行 `scripts/render_style_gallery.py`，将输出的Markdown直接放进聊天正文，不加代码围栏、不另开侧栏。使用本安装目录实际绝对路径，不能照抄开发机路径。每排两个风格，共三排；标题、视频、一句说明在同一个单元格，第三列为空白占位以平衡宿主列宽。表头留空；不要把标题放表头，不加分隔线或把说明另起表格行。视频与说明之间不加br，说明之后统一两个br，把说明贴近上方视频，与下一排拉开同样间距。

视频优先用catalog.selection_preview.file；没有展示副本时用preview_video.file。四个指定首帧已经写入展示副本。3D皮克斯画风的展示副本采用980×420无侧边填充画面，与同排CG写实虚幻风的1470×630同为7:3，保证同宽等高；不添加左右暗边，避免遮住宿主上方圆角的视觉效果。直接使用已校验的展示副本，不在展示时重新压缩、裁切、拉伸或用低清视频替代。保留原采用视频。两列的视频用原生播放器，可以全屏；圆角由宿主播放器决定，不承诺用Markdown控制其内部四角。

每项只有编号、公开名称、原生可播放视频与selection_caption一句说明。不展示原片IP、R03等试片编号、内部preset_id、原文件名、八张参考图、总览和来源介绍。内置八图仍供内部读取和后续资产绑定，隐藏不等于停用。B路线交付外部参考时仍提供实际文件。

不提供单选框、确认按钮或自定义入口；用户在聊天回复1—6或名称即确认。同轮内部读取适用原图、记录选择，然后进入十项剧本分析与全片情绪曲线，不追加“采用／调整”或重复确认。未选择则等待，不自行代选。明确已确认的项目直接沿用，不重复展示菜单。历史自定义记录与C路线既有素材继续可读取，移除新项目菜单不破坏旧存档。

播放样片供用户选择不等于AI已观看或试听；其声音与剧情不成为新项目默认规则。真实核验范围内部保留，不在选择页堆叠检测说明。若播放器无法加载，简短说明并给同名视频链接，不用内置原图代替样片或虚称已播放。

A在P1后用剧本首批人物/代表场景作为试样，采用后再扩大批量；B交付完整提示词、实际独立参考图链接与上传用途，建议先小样但回传自愿。B未回传只记提示词方案确认，不能宣称图像效果已验证。全程只要提示词时不擅自生资产图。

## C已有素材预检

先按 `references/asset_discovery.md` 在用户指定项目范围一次扫描图片、声音和视频；必须实际查看决定风格的图片，视频只在读取了相应画面/动态后才可作为动态依据。读取不到的项目记未验证，不伪造风格识别。初步身份只是建议，正式人物对应关系结合P0A再由用户确认。

预检展示实际文件与可点击预览、类别建议、观察到的风格、拟参考职责和冲突。角色正式资产与服装/色调/空间参考要分开，音频不用于推断视觉媒介。白模、机位截图、黑白设计线稿、历史候选都不能被当作成片画风的多数票。C有合适资产就直接作为自定义风格依据，不要求重复上传另一张风格图。

- 风格统一且用户希望复用：概括主要资产的可见特征，给沿用/调整选择；沿用后确认P0S。
- 风格混杂：先确定正式采用资产与参考职责，给一个主要风格建议及受影响项；用户确认主依据后再锁风格，不静默统一或重做。
- 用户要改画风：列出哪些资产需要转换；转换需按授权局部执行并确认结果，不仅在视频开头加一句新画风，不能自动把C转为全套A。
- 没有视觉资产或只有声音：提示补充视觉素材；用户明确选择纯文字视频时记录 `asset_preflight.status=text_authorized` 及原话，再走内置风格或有图自定义选择，不虚构文件。

预检不做A式资产生产门禁，也不生成四张推测资产清单。十项分析后只确认素材与人物/场景的具体对应及缺口；到P2S复用预检记录，仅核对变化和未确认身份，不重复整套扫描确认菜单。缺声音参考不阻塞。

## 三项独立决定与参考职责

画面媒介、故事世界规则、表演/动作尺度分开记录。先定画风不等于提前替剧本决定能力或伤害规则。P0A负责故事事实，P1把已选画风落实为本片创作标准。分析发现冲突只调整受影响决定，不能悄悄改风格或重跑全部入口。

参考职责使用：`global_style`（造型概括、线条、材质表现、光色）、`look_only`（局部色调影调）、`identity`（角色/道具身份）、`spatial`（布局机位）、`motion`（已实际观看的动态表现）。全片风格图不提供未经授权的人物、家具、建筑布局；角色身份图也不自动统治全片画风。项目已有采用母板继续保留其连续性职责。

## 记录与恢复

按 `references/project_ledger.md` 维护 `workflow_revision=route-style-first-v1`、`style_profile` 和 `asset_preflight`。新模板内置字段，AI填写，不要求用户手填JSON。风格确认是目标选择，不冒充实际样片验收。风格revision改变时标记受影响资产/当前单元待复核，不能覆盖旧采用媒体。每个视频单元记录实际使用的 `unit.style_revision`，重新编译同步。

3.23.17及更早旧项目有有效P0A/P1时从记录继承，不强制重走P0R/P0S；无style_profile的旧记录允许兼容校验，下一次编辑记录时按已有确认补齐 `source_kind=legacy`。旧真人项目不自动改为动画。仅版本升级不代表原资产或成片已被转风格。
