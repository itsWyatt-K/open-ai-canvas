# 场景执行渠道、LibTV连接与结果交付

仅在进入A/B场景资产阶段读取。创作顺序见 `references/scene_assets.md`；本文件不改变人物、道具或C路线，也不启动视频。

## 1. 用用户能理解的方式选择渠道

A由AI生成最终效果图，支持当前Codex窗口或LibTV CLI。B由用户在外部平台生成最终彩图，AI交付完整提示词和上传材料；B场景中的平面图、按需制作的无家具预演台及协作线稿可以由Codex制作，不再套用“B一律不生图/不建模”。用户明确只要全部提示词时尊重其选择。

进入场景时只解释一次，沿用已明确选择：

> 接下来制作场景。A可以在当前窗口生成，也可以连接LibTV，由我上传参考图、填入提示词、执行生成并下载结果。连接LibTV需要你亲自登录、新建画布并提供链接，生成会使用你的LibTV积分。B则由我提供材料和提示词，你在自己的平台出图；建议回传以便协同调整，暂不回传也能继续。

LibTV不是使用本Skill的前提。B用户明确改为AI通过CLI自动出彩图时，仅把场景执行方式记录为A，保留项目原路线及人物/道具成果，不要求从头再来。仅拥有LibTV账号或提供链接不自动改变B的执行责任。其他已连接平台按真实能力执行；没有接口时仍可交付用户手动生成包。

本文件的渠道选择只作用于场景出图。进入视频阶段时，CLI自动执行/不接入原流程由 `references/video_execution.md` 单独承接；场景已连接不等于授权视频自动运行，不接入视频CLI也不取消当前窗口的资产和首帧制作。

## 2. LibTV首次连接

1. 检查当前环境的官方CLI是否存在，读取版本及`--help`；已有安装可用就复用，不强制升级。没有安装时从LibTV官方当前CLI安装说明取得适合操作系统的方法，由AI安装并检查。不把测试机路径写成通用安装位置，不下载来源不明的同名程序。
2. 用当前CLI支持的网页登录流程引导用户亲自完成登录，不索要密码、验证码、令牌或把凭据复制进项目。只安装完成不能记为已登录。
3. 引导用户在自己的账号/目标空间中新建画布并提供完整链接。已有指定画布则复用。校验项目身份，在当前项目目录按`project use`实际帮助完成绑定，并只读核验画布。不继承示例画布、旧测试项目ID或旧账户绑定。
4. 读取当前模型目录和设置schema，确认下节模型及设置可用；展示摘要后按用户授权的当前图片执行。连接检查本身不额外运行收费测试图。
5. 连接失败时说明具体环节，保留已有工作，可选择当前窗口或手动提示词继续；不静默更换账户、模型、项目或渠道。

CLI是画布执行通道，不要求额外配置旧agent-im的access key。命令参数以实际安装版帮助及官方文档为准，不将旧API会话方式误写成CLI前提。

首次彩图执行/首次B彩图提示词交付前，必须核对scene_assets.md 2.2节的参考选择及适用范围；渠道连接、设置已确认不豁免这一步。P0S/P1已有适用且确认的内置风格或global_style时直接复用；缺少有效选择才询问，不能把模型截图或未经确认的P1建议当作选择。

## 3. 彩图默认设置

沿用测试预演台已验证的调用配置：

| 项目 | 默认值 |
|---|---|
| 显示模型名 | General image Pro |
| modelKey | nebula-ultra |
| settings.quality | 2K |
| settings.ratio | 室内16:9；室外21:9；用户明确指定优先 |
| 单次数量 | 1 |

适用于代表房间母板、其余房间首张彩图和确认线稿后的彩图。首次按当前场景告知“General image Pro、2K、室内16:9（室外21:9），每次一张”并写清本次实际采用的比例，之后沿用，不逐图重复询问。用户已明确其他场景画幅/设置时沿用并说明与默认差异。设置不支持时如实说明，让用户决定替代，不悄悄降档或换模型。

黑白线稿默认在Codex内生成，不使用LibTV的Lib Image，也不把旧线稿参数`quality: medium`带入彩图。Codex实际模型/尺寸由可用工具决定，不承诺与LibTV底层模型相同。其他渠道不能声称使用General image Pro或同一质量档。

2K是调用档位，不等于固定尺寸。测试预演台在21:9档返回过3168×1344，略偏离严格7:3；逐张记录原生宽高与实际比例，不自动拉伸、裁切或放大来宣称原生规格达标。

## 4. 每张图的执行与回传

A＋LibTV：准备真实参考文件 → 上传/复用资源节点 → 建立生成节点及实际连线 → 核对图序与提示词逐图职责（外部风格图仅色调/调性/影调，不提供内容） → 检查设置 → 运行 → 读取结果 → 下载原图 → 展示、检查和确认。当前可见关键道具母板必须实际连接；核对imageListOrder/imageList或当前CLI等效回执，只写道具名不算绑定。参考变化后重新连续编号。失败重试前先查节点/任务状态，防止重复计费；同一问题连续两轮失败按 `references/asset_review.md` 换方法。

A当前窗口：按同样输入职责直接生图，展示并保存可取得的实际结果。只有聊天预览不能声称本地原图存在。

B手动生成包：交付当前房间/机位的编号素材（有文件用可点击链接）、上传顺序及职责、按scene_prompt.md编写的简洁完整中文提示词、代码块外的平台实际设置和建议回传文件名。没有文件时写“请上传你已选定的某房间彩图”，作为外部上传计划，不伪造本地路径或平台连线。

回传是建议，不是B门禁：可上传聊天、放入约定本地目录供读取，或暂不回传继续提示词。未回传时依据剧本、确认文字设计和外部参考占位继续；说明家具细节、未知背面和光源尚未对照实际结果。用户说已采用外部图可记录其声明，不能记AI视觉通过或本地归档完成。需要Codex对照该彩图画线稿时再建议提供；仍不提供则交付外部平台线稿提示词，或用户选择的未对照实际彩图的设计提案，不阻塞整条B路线。

## 5. 保存与收尾

每轮结果及时保存，每次采用及时按 `references/asset_delivery.md` 发布。项目`00_最终确认资产/03_场景`只放当前已确认彩图，默认平铺，名称区分场景/房间、机位、状态与版本。平面图、预演工程、机位截图、参考、线稿、生成记录及历史/失败彩图放项目外工作根目录；旧项目按该文件的迁移规则处理，不再无条件沿用杂乱目录。保留原件，不覆盖不同内容。记录实际文件、真实像素、参考来源、采用/待审状态和确认依据；彩图关联所用母板及适用线稿版本。

LibTV自动下载成功后不要求用户再上传同一结果。画布按房间/类别分组，待审与采用分开，保留历史节点和连线；进入“最终图”组不代替用户采用。本地保存失败要明确缺口，不把远端生成成功当成本地完成。

B只交提示词也可完成约定交付，结论写“提示词已交付，外部图片未回传/未归档”，不强制等待。收到的实际图片按同一规范归档。A实际图片交付与B提示词交付分开记录；视频入口仍遵守原P2S规则。
