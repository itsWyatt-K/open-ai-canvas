# 导演旗舰版阶段与授权（唯一交互规则）

## 1. 基本约定

内部维护当前记录，外部只推进当前一步。资产代验收授权与只测到场景的范围统一按 `references/asset_review.md`；下文视频流程只在run_scope=full时执行。固定确认包括：新项目路线与P0S风格、P0A整体、P1基准、当前路线资产成果、实际素材身份、缺失的项目设置、每段P3A文字AI导演提案的原文范围/安排、随后草图具体版本（含已展示首镜）及交接选择；P3B新增输入图另确认。视频固定无BGM；内部检查通过不能替代首帧用户确认。已有用户明确答案不重复询问。

通常恢复时不重做已确认的P0A/P1，只显示当前阶段、已确认事实、原文位置与唯一下一步。用户明确要求从某阶段重新测试、逐项重新确认或不继承旧决定时，仅在其指定范围重新确认，旧成果保留为历史；不能借恢复原则跳过本轮确认，也不能擅自重启范围外的资产制作。项目aspect_ratio只记录后续视频目标画幅；草图整图和各格独立排版，按实际画格数选择。需要作为平台输入的独立首帧才核对视频入口规格；资产母板版式独立。

### 任意阶段调用预演台

已取得剧本时，用户直接输入“预演台”或要求创建/搭建，按 `references/previs_entry.md` 执行独立分支；A/B/C及当前阶段均不构成限制。先回读剧本，列出全部物理场景和数量，支持单选/多选，再制作所选平面图；本批图纸全部明确确认后才初始化和搭建模型。已有有效范围/图纸确认沿用，仅提示词确认不能代替图纸确认。打开或续做已有工程则恢复，不重新建模。

保存原路线、阶段和待答版本。模型交付确认后，独立任务可结束，继续制作则返回原节点；只在原任务确需场景彩图时进入彩图链。C不被强制补人物、道具、彩图或重走完整分析。图纸和模型确认不替代P3A/P3B视频门禁；具体记录见project_ledger.md。

### 自动代确认仍需可见交付

自动化、委托代理选择或跨任务监督只改变谁作决定，不取消向用户展示成果与阶段引导。收到有效全流程代确认授权时，代理可在实际看过具体成果后直接决定并继续，不重复要求用户回答；但必须先在用户跟进制作的聊天中展示成果，再说明“依据用户委托代理采用[具体版本]”及下一步。跨任务时在执行任务保存完整成果，并在监督窗口同步宫格提案实际图片、短说明及采用依据；仅发送后台任务消息、文件路径或“方案已采用”摘要不算展示。未授权的范围仍等待用户决定，不能把资产代验收扩大为全流程代确认。

每段P3A先展示并确认文字AI导演提案的原文范围和简述，再生成一次宫格草图、列出问题并等待采用/修改，最后核对首镜依据。可把两段总体计划先作预告，但后续单元仍在其开始前展示当前有效提案，明确前一段实际结果带来的衔接修订；不能凭最初的一份全片计划省略后续段落。若本段提案已在当前交付聊天展示且内容未变，不为套格式重复；只有后台文件或另一个任务内的提案不满足当前窗口展示。

### 文字编号选择（所有阶段共用，不使用弹窗）

需要用户选择或确认时，统一在聊天正文中展示问题及本轮全部适用选项，每项独占一行，采用“编号｜明确结果”，通常2～3项；用户回复`1`、`2`、`确认1`、`确认2`即可，也接受原有自然语言。适用于A/B/C三条路线及CLI/不接入两种执行方式中的路线、范围、参考、资产验收、回填、平台设置、导演方案、首帧、视频采用及声音修复选项；不要只在首段采用，后续回合又要求复述长句。不调用`request_user_input`、`request_user_input_async`或其他弹窗、选择按钮、表单工具来承载这些问题，也不把选项只放在附件或后台消息里。

- 需要真实用户回答时，将问题与完整编号选项保留在本轮最终回复中，结束本轮等待下一条用户消息；不设置默认等待时限，不轮询倒计时，不因超时、未回复、预选、界面关闭或任务恢复而自动采用。可先完成不依赖答案的工作，但不能启动依赖该答案的生成、采用或下一阶段。恢复时沿用仍有效的待答问题；用户仅提问时先答疑，未作选择的门禁仍待答。
- 上文有效的代理代确认授权仍按其范围执行，并在聊天中明确说明所选编号、结果、具体版本与委托依据；不伪称真实用户已回答。用户停止自动化或撤回代确认后，停止代理选择及自动推进，后续选项等待真实用户回答；历史委托不能自行恢复。

- 每轮优先一个当前决策；同一阶段可合并具有明确共同结果的选择，例如“确认本段方案＋交接开/关”。已确认设置沿用；建议必须明示，不把排在第一项、预选或未回复当作确认。不强加推荐项。
- 数字只解析为当前最近一组仍待回答、已向用户展示的选项。记录该组选项所属阶段、单元/资产名称、具体版本、编号含义与提问出处；收到选择后把用户原回复及其完整含义记入现有确认来源。不要另建逐条选择文件。新版本/新组选项使旧选项失效；跨任务不借用数字含义。
- 只有解释同一待答问题的补充说明不改变编号；用户提供了新修改要求则先处理修改，不同时把数字当作采用未生成的新版本。无有效选项、数字越界、`1/2`等含义不清或跨版本歧义时，只澄清具体歧义。镜号、时长、模型版本、正文编号不自动当作选择。
- 多场景/多资产选择显示独立对象编号，明确支持“全部”“1”“1和3”等；一次只提供这一组编号，避免把“场景1”和“操作1”混列。批量采用必须写清实际名称、范围、版本；单张确认不扩展到整批。
- “1｜采用[名称/版本]；2｜修改＋修改要求”可用于审图；用户选2但没给要求，只问哪里要改，不擅自重做。参考选择可用“1｜我提供风格参考；2｜按已确认P1设计”，选1后等待实际参考，不把数字当作图片已上传。B选择仍遵守回传自愿。
- 视频设置按P2V的顺序逐项展示具体菜单，不合并成参数组合，也不在一轮堆多个含义相撞的数字菜单。用户一次明确给出多个值时直接记录，只问剩余项。路线可显示“1｜A完整资产；2｜B提示词协作；3｜C已有素材”，内部仍记录A/B/C。
- 用户要求逐项确认时逐项列出可行编号选项，但不增加原流程没有的确认关卡。切换为文字、重新展示或解释同一问题时保留完整选项和有效编号，不退化成无选项的开放式问题。路径、上传文件和修改内容确实需要自由输入时，明确需要什么及用途，不伪造可代替实际输入的选项。
- 选完后一句说明已选结果与唯一下一步；下一步仍需回答时，同一回复必须同时展示该问题的完整编号选项，不能只写“接下来选择模型/画幅”或只抛出问句。满足前置且已有授权就继续；不再问“是否确认刚才的选择”。P3A宫格确认可以覆盖图中已展示首镜，P3B不重复询问同一构图；新增的彩色输入帧或变更图必须展示后才可采用。用户要求修改可直接描述，不必先回编号；事实说明、故障和自由创作要求不强行改成选择题。


### 每轮提问的可见交付检查

各参考文件中的“询问、确认、澄清、让用户决定”都必须落实为本节的可答选项，不能把内部流程描述原样当成用户问题。此要求适用于每一轮，包括收到上一轮数字答复后的下一问、失败恢复和后续片段，不只检查平台入口。

发送前检查当前实际回复：问题后是否紧接完整编号选项；每项是否写清具体对象/版本及选后结果；是否告知回复方式。任一缺失先补齐再发。只问“使用哪个模型版本？”“画幅多少？”“是否采用？”属于未完成交付；不以后台菜单、上一轮选项或台账代替。改为文字问题后同样检查。没有待决事项就不新增提问。

| 当前待决事项 | 应展示的选项内容（实际发送时逐行展开并填入具体名称） |
|---|---|
| P0A解析、P1基准、清单或批次提示词 | 1｜确认[具体成果/版本]并进入[下一阶段]；2｜修改[成果]，说明要调整的部分 |
| 角色、道具、布局、模型、线稿、彩图 | 1｜采用[具体版本]；2｜修改[具体版本]，说明位置与要求；已有明确授权/选择不重问 |
| 素材全量盘点 | 1｜采用本表图片、音频、视频的身份及版本建议；2｜调整，列出素材名称及修改；缺声音只提醒，不加补音选择 |
| 人物/素材身份或范围有歧义 | 列实际候选及其差别，每项编号；最后可加“自行说明其他身份/范围”，不让用户凭空猜候选 |
| 场景建模、风格参考与回填 | 独立预演先按previs_entry.md列全部场景编号供单选/多选，再确认所选图纸；A/B常规出图分流仍保留直接出图、无参考、跳过等分支 |
| 视频平台、LibTV执行方式、模型、画幅、分辨率 | 使用P2V的具体菜单；不能用这一行或“请选择参数”替代菜单 |
| 文字AI导演提案、草图与交接 | 使用本文件P3A及handoff_frame.md的编号选项；先确认原文范围，再一次草图；不自动重画 |
| 已生成视频、剪辑成片、声音精修结果 | 展示当前结果和问题后，1｜采用[具体版本]；2｜按列出的[具体修复方案]修改；可再列“提出其他修改”，不只问哪里不好 |
| 真实失败/能力不支持需要改方案 | AI先诊断，列当前可行处理方案及影响供编号选择；无可行替代时说明缺什么和如何提供，不编造可执行选项 |

确需文件或自由文本时，也给明确提交方式，例如“1｜直接上传[所需文件]；2｜提供本地完整路径”，或“1｜说明要改的镜号/位置及内容；2｜保留当前版本”（只有可保留时提供2）。用户可直接提交，不必先回数字；选上传/路径方式不等于已交文件，不能据此推进。用户已选上传而文件尚未到时，只提醒待上传，不反复选择提交方式。纯情况说明、内部自检问句和用户主动问答不属于新选择，不硬添菜单。

### 视频阶段：导演先给方案，用户确认可见结果

“逐项确认”指确认成果、偏好和真实缺口，不是让用户完成导演工作。原文起止、拆段、时长估算、镜头/表演、一镜到底或打斗形式、素材需求、平台能力和故障诊断先由AI完成；不将内部检查项逐个改成用户问题。每个需要选择的问题先给具体对象、可见结果或影响说明，再列编号选项。

| 环节 | AI先完成 | 需要用户决定的内容 |
|---|---|---|
| 视频入口/恢复 | 读定稿、指定重测范围与当前进度，定位有效待办 | 仅真实冲突的剧本/任务范围；列具体候选及建议，不问“你想从哪里开始” |
| 素材 | 扫描实际文件、核对身份依据、整理已有项与缺口 | 实际身份/采用版本和明确缺口的处置，不要求判断全片专业完整性 |
| 设置 | 核实可行平台参数及当前已答项目 | 尚未确定或用户要求重选的参数、执行方式；CLI执行前补实际连接信息 |
| 导演提案 | 先给本段完整原文和逐镜简述；确认后生成一次宫格草图并列问题 | 先确认原文结束位置与安排，再采用/按格修改草图；交接按handoff_frame.md选择 |
| 输入帧 | 沿用已确认首镜，判断是否确需新图并制作/核对 | 仅新增或改变的实际图；同一构图不重复确认 |
| 提示词与生成 | 编译、内部校验；manual完整交词，CLI直接执行并返回视频 | 有明确授权即可执行；不新增重复许可或要求用户判断槽位、校验字段 |
| 验片与修复 | 检查实际结果，指出问题位置、影响、可保留内容和最小修复方案；说明未能查看/听音的范围 | 采用当前实际版本或选择具体修复；不问空泛的“怎么修” |
| 剪辑与交付 | 在已授权范围剪辑、检查接缝和声画，展示真实成片 | 成片采用/修改；BGM仅由用户另行提供实际视频并主动要求时开展 |

首次制作或明确从头重做，由AI从指定剧本范围开头拟定第一段；续做时优先处理当前尚未完成的单元，再到下一未完成节点。重新询问平台设置不等于删除旧进度或默认重拍：若“重测流程”与“继续旧片”确有歧义，先展示两种具体任务及影响供选择，不让用户查找原文或自己拆段。原文边界与简短镜头安排先在文字AI导演提案中确认，再生成草图。用户明确指定其他场次或原文时从其范围设计。

按用户指定入口可先重选P2V设置；完成后回到尚未完成的实际素材确认，再进入宫格提案。不能因为CLI已连接而跳过素材，也不能重新询问本轮刚答过的设置。旧项目字段与本轮重测记录冲突时依据最新明确指令核对，不能只读一个“唯一下一步”标签盲目照问。

### 阶段收尾与下一步引导

所有制作阶段的可见交付都要交代“当前完成什么及状态、现在可确认或修改什么、接下来具体做什么”。适用进度从现有记录汇总。已有授权时用“已采用，接下来执行……”并继续，不再伪装成待答选择。资产图额外遵守下列三项完整收尾；非资产阶段按文末的阶段表收尾，不硬套图片数量。普通问答和暂停按本节既有例外处理。

每次资产图生成、修改、确认后的最终回复必须带下列三项收尾，适用于人物、道具、室内外场景母板及补充机位；线稿、平面图用各自阶段名称。图片工具返回结果、图片下的文件链接或过程中的commentary都不能替代最终回复里的引导。其他文件中“只展示图片”“只交付修改稿”“一句下一步”均须保留本节三项，不可省略；用三句短文或三条短列表即可，不重复整张流程表，不写入生图提示词。

1. **当前结果与操作**：指明名称、用途、具体版本和状态，附实际图或可点击链接；待审时明确邀请用户确认这张/这批，或指出要改的位置、内容，并给当前最关键的一至两项检查点。内部检查不等于用户采用。用户不认可时继续修改本项，新稿继续待审；未答复不自动采用。批量出图支持逐项/部分确认，不把一张确认扩展到全批。回复指代不清且有多个版本时只澄清歧义。
2. **确认后的动作与下一步**：待审时用将来时说明“确认后命名并归档至最终资产目录，再制作[下一项具体名称/动作]”；不能提前说已存为确认版。收到有效确认后，同轮先按 `references/asset_delivery.md` 复制核验实际文件、采用命名、更新当前指向和总览，再提供确认文件/总览的绝对路径链接，说明下一步。落盘失败须说明“图已确认，归档未完成”，保留待办并修复，不能报告交付完成。下项已有授权且前置满足就继续；尚需参考选择、线稿确认等前置时，下一步指向该前置，不跨过门禁。
3. **阶段进度**：从现有已确认范围与逐项状态汇总，显示“[范围]共N项：已确认A，待确认B，待修改C，未生成D”；同时点名下一项及其余未生成项，较多时只列紧接着的二至三项。零值可省略。不能用磁盘图片数量推算，不让用户自己数文件。范围未确定时说明尚未确定总数，列已知待办，不虚构N或完成百分比。

状态与计数口径：
- 同一资产身份＋剧情状态＋机位＋用途算一项，V1/V2等修订不增加总数；每项在当前需求进度中只占一个状态，N=A+B+C+D。待修改优先于待确认；需要修改的当前项不能一边待修改一边记需求完成，旧采用副本仍可按归档规则保留。
- 人物9:16稿与人物信息版是两个子阶段，各报各的进度；线稿与最终彩图也分开计数，线稿通过不能增加彩图已确认数。场景先报“已选房间基础彩图”，补机位另报“已选扩展机位彩图”，不把尚未选定的建议反打、特写或未选入制作范围的场景自动加进总数；已选直接出图的场景仍计入其彩图范围。

### 第二步：宫格分镜草图，每轮只生成一版

依据已确认文字方案，按proposal_storyboard.md统计实际画格数量并选行列和整图比例，再发起一次草图生成，打开本次结果并直接展示。标题使用“第N段｜宫格分镜草图 Rx｜待审”，保留简短镜号/时间/表演说明。检查只用于列问题，不自动纠错重画；不为身份、门牌、比例、线条风格、手部、文字标签或非目标格漂移反复生成，也不并行生成多个候选供内部择优。

若发现问题，在图后用短列表写“格号＋可见问题＋与已确认文字方案的差异”；没有明显问题则一句说明。草图用于观察大概分镜效果，不要求达到正式资产质量。用户可以在知悉问题后按文字方案采用草图作为示意；记录保留问题，不把“采用示意”说成视觉检查全部通过，不擅自把错误画面写为剧情事实。

交接已确定时逐行提供：

1｜采用当前草图，按已确认文字方案继续

2｜修改草图（说明格号和要求，或采用已列的具体修改建议）

交接尚未确定时按handoff_frame.md解释并合并编号选择，同时保留“修改草图”选项。T/T+1先检查实际入口上限。原文范围和安排已经确认，不重复发起同一文字审批。

用户明确提出修改某格即授权该次修改：只生成一版修改稿，展示差异及仍有的问题，等用户决定。用户明确说“重新生成”时只重试一次；“继续”、一般质量代验收或历史自动化授权不等于允许循环重画。每次生成/修改的请求、版本及问题写入现有记录，不建立额外逐图表单。

生图失败时说明失败且没有可用草图，不自动重试；显示已有文件的路径或界面问题可排查，但不得借此再次调用生图。仅用户明确选择重试或本段文字例外时执行对应动作，不能因失败静默跳过草图。

用户采用本版草图后记录图像确认和未修问题，进入P3B；只有文字确认、已写文件或AI自检都不算图像采用。此单次草图规则适用于A/B/C、CLI/manual及视频阶段所有宫格、独立首帧草图和局部修改，不影响资产阶段既有制作范围。另需正式彩色输入图时先说明用途；生成后有问题同样列出供用户决定，不自行启动循环修图。

## 4. P3B：首镜依据与平台输入准备

按 `references/first_frame_storyboard.md` 核对已确认宫格的第一镜、第一状态及构图可读性，不要求草图首格匹配视频比例。首镜已经实际展示且被本版宫格确认覆盖时，preview记录kind=grid_panel、图来源、格号、镜版本和确认来源，直接进入P4，不另外重画或重复确认相同黑白构图。内部通过、只有文字提案或仅修改指令不能冒充图像采用。

平台确需单幅输入时，按实际入口准备无分格、无编号说明的单幅图；整张宫格不得作为视频首帧或默认参考。新增彩色帧或实质改变的首镜展示确认后再绑定。只改后镜而首镜未变，保留原首镜确认；改首镜则返回P3A修对应格并展示，新版确认后更新preview；每轮只生成一版，有问题列出待用户决定，不自行修图。原单幅首帧确认记录可保留真实来源；旧采用视频不追溯重做，下一新段执行宫格流程。

明确授权的宫格例外不自动跳过首帧；首帧无法生成时亦需用户明确本段例外来源及原因才可text_fallback，不能把两个门禁混为一个。


## 5. P4—P5：编译与交付

P4不形成用户回合。根据prompt_form编译当前已确认宫格：shots对应镜号/时间/切点；one_take对应单镜连续状态；combat对应攻防阶段、连续时间预算及关键状态，阶段内明确机位、快切与特效，不强制一格对应一次切镜；用户明确无摄影的简式过程只核对关键状态与总长。具体结构按prompt_templates.md；同步compiled_storyboard_revision，不能沿用修改前的旧词。局部角色声音引用与素材槽位按实际最终集合建立；图片、音频、视频各自从1连续编号。按director_quality_gate.md运行状态校验、提示词校验和一次语义冷读。

记录stage=P4准备交付时，当前unit导演确认、交接、固定无BGM状态、素材、依赖及预演状态必须完成；不能仅填voice_mode或P5标签绕过门禁；无本地声音参考不是未解决门禁。

manual或用户主动索要提示词时，首版依次交付：
1. 已确认宫格版本及首镜依据摘要（无需重复确认）；
2. 实际上传映射，文件使用绝对路径可点击链接；无素材写本批无需上传素材；
3. 代码块外【本段生成信息】；
4. 一个完整视频提示词代码块，从【风格锁定】开始；
5. 代码块外一句下一步引导，按已选执行方式推进；不附带任何配乐提示词。

CLI默认把上述映射、生成信息和完整提示词保存在内部编译文件，用于同一套校验及上传；只简述本段参数与即将生成的动作，前置与授权齐备便直接上传、运行和返回视频，不等待“展示/确认提示词/下一步”。不把完整提示词作为默认附件、链接或折叠内容展示。用户索要时按上述格式展示当前版本；单纯查看提示词不触发重新生成。首版和修改稿均遵守此分流。

正式提示词不能包含制作流程解释、总时长前导行或全局交接启停说明。修改稿默认生成信息＋完整新提示词＋代码块外一句下一步引导，不附带BGM/Suno。

交付后的推进先判断用户正在回复哪个具体产物和当前执行状态，不把“满意/采用/下一步”统一解释为下一段：
- 仍有待答门禁时，“下一步”不能代替缺失的具体选择；只有语义明确指向当前展示版本的采用答复才记录相应确认。
- 当前只有提示词：manual说明如何生成；用户明确要下一段提示词时才推进提示词进度。cli且执行授权及前置齐备时生成当前段，不跳到下一段，也不重复索要同一执行许可。
- 当前生成已提交、仍待结果：查询原任务并等待，不重复提交、不跳段。结果不明先核查。
- 当前实际视频已展示待审：明确采用该版本才记录采用并按任务范围继续下一段；仅“下一步”且是否采用有歧义时，给“采用当前视频并继续／保留待审，仅做下一段提案”等具体选项。
- 用户明确只要下一段提示词或指定第N段时，可以推进对应创作；前段实际视频仍保留真实状态，不把跳过生成或未回传记为采用。

只确认提示词不意味着实际视频已采用。实际视频已采用而任务范围已完成时进入剪辑/交付，不凭空创建下一段。

首版和修改稿都须保留本节收尾引导。CLI模式默认隐藏提示词，内部编译校验通过后按已有执行授权直接运行并返回视频；不接入则按原流程交付给用户操作，不索要CLI或远端节点。实际视频生成不是P4内部编译的一部分。

## 6. 修订授权与依赖

本节是所有文件共用的修订规则：
- 用户明确要求局部修改就直接执行，不重复询问是否允许修改；视觉/表演/镜序/时长变更先按proposal_storyboard.md更新目标格并展示，新图确认后同步提示词。纯音频绑定、错别字修正等不改变画面设计时沿用宫格，记录authorization=user_revision及来源，不重审整段。
- 用户只描述异常、尚未指定解决办法时，先诊断；如果同时要求修复，可以在不改变原文与方案核心的范围内修复。仅要求分析时不修改。
- AI拟新增/删除剧情、改原文边界、改核心导演意图，且超出用户本次明确授权时，展示最小差异再确认。明确要求这些变化的用户指令本身可作为授权，不机械再确认。
- 不相关已确认部分保持。改动导致后段依据过期时登记待重检，只重检有关内容；已采用视频保持原文件，不自动重生成。
- 素材增删后同步内部上传计划与正文全部合法引用，修改稿不强制重发外部表。新文件身份未确认时只询问真实缺失的身份，不能虚构确认。
- 当前单元修改沿用有效交接选择；音乐固定none。旧音乐计划移交独立成片后期，已采用视频保持原文件，不自动去音乐或重生成。

## 7. P6/P7记录、恢复与完成

实际视频采用后记录素材来源、采用区间、结束状态及依据。只给提示词推进词时保存planned_end，adopted_end保持未确认。新段重建自包含首帧，实际采用状态优先作为连续性证据；若与剧本冲突，标记并请用户决定，不用生成错误悄悄改剧本。

恢复时保留所有确认；素材变更只确认变化项；画幅/版本/平台缺失才补问。旧记录迁移先另存，再补齐当前execution事实；没有证据的字段标记待确认，不整批设为true。

按 `references/postproduction.md` 把实际采用单元加入工作剪辑，场景和全片画面锁定后再做统一声音精修。独立“母带级处理/母带处理/声音精修”请求走 `references/audio_finishing.md`；用户主动上传/指定实际成片配乐走 `references/post_music.md`，二者不受剧本阶段限制，也不新增自动配乐问答。独立配乐已选不接入时，读取视频后直接交完整BGM提示词；本地剪辑和已有音轨混音不依赖CLI。

用户范围全部覆盖后检查原文有无漏段/重复、台词覆盖、关键连续性未决项及音乐重复。区分“提示词交付完成”和“成片制作完成”：前者不要求用户回传视频；后者需用户采用证据。完成依据记录在completion.kind与evidence中，再进入COMPLETE，不以最后一条提示词交付冒充全片成片完成。

## 8. 交互回归的覆盖边界

用户要求流程/自动化测试时，按其授权范围记录以下场景的实际消息或可见产物；未运行的写未测，不因生成了视频而整表判通过。复用现有问题日志，不新增逐步骤表单给创作者。

| 场景输入 | 应实际观察到的行为 |
|---|---|
| C路线任意阶段仅输入“预演台” | 回读当前剧本，列全部物理场景及数量供单选/多选；不直接建模，不要求改选A或补齐资产 |
| A/B非场景阶段要求为场景1和3创建预演台 | 列剧本场景并沿用明确范围，只出选中图纸；确认后才建模，完成后返回原阶段 |
| 所选两张图纸仅确认其中一张 | 另一张仍待确认；未经明确改为先做已确认子集，不开始本批模型 |
| C已有场景彩图但没有平面图 | 区分可见事实与推断，先制作图纸供确认；不将透视彩图或提示词确认冒充平面图确认 |
| 从平台开始重测，要求每项重新确认 | 仅在指定范围逐项展示编号选项，保留本轮已答设置；素材核对后先由AI给原文范围和文字简述，用户确认后才画一次草图 |
| 要求把当前问题改成文字版 | 问题和全部有效编号选项均出现在聊天最终回复；不调用弹窗，不丢失选项，不设超时默认采用 |
| CLI当前段内部编译完成或旧版已交词，尚未生成 | 前置与执行授权齐备则生成当前段；已运行则查询同任务，不跳到下一段或重复提交 |
| 已取得视频，仅回复“下一步”且是否采用不明 | 展示针对当前版本的具体选择；不把含糊回复记为采用，不要求用户自己诊断修复 |
| 已采用视频需要连续性参考，已有本地处理授权 | AI按需抽帧、核对；仅作内部判断不占槽位，新增平台输入图展示确认后才绑定 |
| LibTV平台，明确不接入CLI | A/B/C原路线保留；先确认文字提案，再展示一次草图并确认已展示首镜，交完整提示词与手动下一步；无安装/登录/远端节点阻塞或自动运行 |
| 已授权CLI自动出视频 | 先确认本段文字提案，再生成一次草图展示采用；沿用首镜，新增输入图另展示确认，完整提示词内部编译校验后直接上传并运行、返回视频，默认不展示提示词；用户索要才展示，已有授权不再重复询问 |
| 全自动代理开始下一视频单元 | 当前窗口出现该段有效提案及实际连续性修订、代理决定和下一步，不能只有“已采用”或后台文件 |
| 指定镜03修改 | 实际只修改一次目标格，其他格对照检查；有漂移列出，不自动重画；新图展示后确认，旧宫格/提示词确认不可冒用，必要衔接同步 |

| 3D已确认，用户说否/没有 | 明示无参考、按P1与剧本继续，不再重复确认；没有答复则不能走此分支 |

| 每阶段的出图/修改/确认/交付 | 当前结果与版本、可操作内容、唯一下一步可见；资产进度按本批范围准确，确认后实际归档再报告完成 |

有/无参考与CLI/不接入须分别测试，不能拿代理选“无参考＋CLI”的一次实测覆盖其余分支。展示核对属于对话验收；脚本回归只说明状态/提示词检查逻辑通过，未实际生成或听辨的项目单列。
