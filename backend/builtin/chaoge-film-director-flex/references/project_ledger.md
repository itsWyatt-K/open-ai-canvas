# 项目记录、轻量状态与连续性真相

## 1. 按路线选择记录类型

聊天记忆只帮助交流，不替代跨天、换对话或上下文压缩后的项目状态。记录的目的不是检查用户电脑，而是保存已经确认的导演事实、当前进度和下一步。

- A路线使用完整资产台账：复制`assets/project-ledger-template.md`到项目目录，建议命名为`项目名_资产台账.md`。
- B、C路线使用轻量制作状态：复制`assets/project-state-template.md`到项目目录，建议命名为`项目名_制作状态.md`。

不要把任何项目记录写回Skill目录。B、C的轻量状态不得保存本地文件路径、哈希值、图片尺寸、目录扫描结果或“文件已验证”结论；用户也不需要手动维护，由AI在关键确认后自动更新。

## 2. 真相优先级

发生冲突时按以下顺序处理：

1. 创作者明确确认采用的最终剧本版本；
2. 创作者确认的P0A、国家年代、世界规则、人物小传和P1创作基准；
3. 创作者确认的资产范围、生产路线和单项处理方式；
4. A路线中确认的角色、场景、道具和色卡母板；
5. 创作者明确确认采用的剪辑成片或生成视频；
6. 从采用视频中提取的连续性帧；
7. 已确认动态资产；
8. AI推演和未确认描述。

用户声明“已有”可以成为C路线的准备状态，但不等于AI已经访问或验收文件。生成成功也不等于采用。每个阶段记录当前确认门禁和确认后的唯一下一步。

## 3. 版本字段

- `skill_version`：本版为`2.0.0`。
- `record_schema`：本版为`2.0`。
- `record_type`：`full_ledger`或`light_state`。
- `script_version`：用户的剧本版本名。

旧记录主版本不兼容时先按`production_routes.md`生成迁移预览，创作者确认后迁移。不得改写既有剧情、美术、连续性和采用视频事实。

## 4. 共同字段

- `production_route`：`A_full`、`B_prompt_only`、`C_direct_video`或`待确认`。
- `batch_material_mode`：`mapped`、`text`、`hybrid`或`待确认`；项目字段只保存当前/默认值，每个导演单元仍可覆盖。
- `voice_mode`：`mapped_dry_voice`、`model_voice`、`post_dub`或`待确认`。
- `current_stage`：当前流程节点。
- `platform`与`model_version`：平台确认后登记。

生产路线只决定P2。视频素材方式和声音方式按批次决定，不反推项目路线。

## 5. A路线完整资产台账

A路线使用永久资产ID，ID不随某条提示词的上传顺序改变：

- `CHR-角色-状态-序号`：角色母板、角色设定板、变异、换装和受伤状态。
- `SCN-地点-视角-序号`：地图、外观、房间、方向板、色卡和确认的360度抽帧。
- `PRP-道具-序号`：关键道具。
- `DYN-Uxx-用途-序号`：镜头专属动态资产。
- `CNT-Uxx-用途-序号`：采用视频抽帧或连续性桥接图。
- `AUD-角色或用途-序号`：声音身份和声音参考；不表示本地干声已经准备。
- `VID-Uxx-TAKExx`：候选视频；只有采用版本标记`已采用`。

A路线可以记录真实可访问文件路径、来源、验收状态和唯一职责。状态只使用：`待生成`、`候选`、`待修改`、`已确认`、`已采用`、`弃用`。提示词确认不得伪装成图片确认。

默认资产目录为`项目名_资产/01_角色`、`项目名_资产/02_道具`、`项目名_资产/03_场景`。只有A路线需要把目录用于生成、验收与连续性管理。

## 6. B路线轻量状态

B路线只记录：

- 剧本版本、P0A和P1确认状态；
- 当前资产类别、当前提示词批次和下一批；
- 上游资产名称与下游依赖关系；
- 每批提示词的`待输出/待确认/已确认/需修改`状态；
- 最终声音准备方式；
- 平台、导演地图、当前视频单元和连续性快照。

不记录外部平台生成了哪张图片，也不要求用户回传或证明图片存在。提示词内的`{{Image N}}`仅是外部生成时的上游操作槽位。

## 7. C路线轻量状态

C路线保存创作者最终确认的4类资产范围及处理方式：

- 人物、道具、场景：`已有可用`、`自行补充`、`文字承担`、`删除`；
- 声音：`已有干声`、`自行生成或寻找`、`模型配音`、`后期配音`、`删除`。

同时记录平台、导演地图、当前视频单元、本批素材方式、本批上传ID映射、已交付提示词版本、采用视频和连续性快照。不得保存用户资产的本地路径或制造“已经上传/已经验收”状态。

四张资产表就是C路线的资产范围记录；无需另外生成完整资产矩阵。

## 8. 当前批次上传映射

项目永久名称和平台临时槽位分离。每个视频批次按用户实际操作顺序重新排列为`图1`、`图2`、`音频1`、`视频1`。轻量状态记录的是“用户上传计划”，不是文件存在性证明。

每行只保留：`提示词槽位｜资产名称｜准备状态｜唯一职责`。准备状态可为`用户已有`、`待用户准备`、`本批不使用`。提示词引用的每个槽位必须出现在映射中；没有视觉素材时不得创造图号。

## 9. 连续性快照

每个采用视频至少记录结尾：人物位置、面向、动势、情绪余波、服装、伤势/变异、手持物、场景光线、门窗与破坏、屏幕运动方向、轴线、环境声和BGM状态。

如果下一单元无需严格连续，只登记事实，不强制抽帧。需要连续时可以登记最短尾段、真实首帧、仅站位参考、背景状态参考或桥接图。B、C只有在用户主动回传并确认采用素材时才登记这些载体，不扫描本地目录寻找。

## 10. 更新时机与显示

以下事件后立即更新对应记录：路线选择；P0A/P1确认；A资产确认；B提示词批次确认；C四表范围确认；平台与导演地图确认；本批映射和提示词交付；视频采用或弃用；连续性事实变化。

默认只向创作者显示“当前阶段、已确认事实、当前批次、下一步”4行摘要。完整记录只在用户要求查看、需要迁移或发生冲突时展示。

校验命令：

```powershell
python -X utf8 scripts/validate_ledger.py <项目资产台账或制作状态.md>
```

（在源起 Agent 运行时内，直接调用工具 director_validate_ledger 执行同等确定性校验；离线 CLI 环境运行上述脚本。）
