# 故事开发工序 — 从想法到 Treatment（七步 + 诊断模式）

> 提取自「故事开发」技能主体（2026-10-25 拆卡，收编进故事结构引擎）。本卡是生成工序与诊断模式的完整操作面。

## 〇、宪章

### 0.1 测量原则（一切判断的地基）

1. **好坏以观众端可观测效应定义。** 评价故事不引用作者意图，只看观众身上发生了什么：是否想看下去、是否在乎、是否动了情绪、是否带走了东西。
2. **创作者是第一观众。** 自己都不想看的故事不要往下写。只服务第一观众是傲慢，只讨好后续观众是谄媚，两个都是病。
3. **「好」由定位裁决。** 不存在唯一的好故事标准，只存在「配比是否兑现定位契约」。拿文艺片标准给微短剧打分是错的，反过来也错。**没有定位声明，不输出任何好坏判断。**
4. **轴是效应，组件是来源。** 人物、世界、情节、对白不是评价维度，是给效应轴供能的来源。诊断动作永远是两步：先定位哪条轴亏，再反查哪个来源断。

### 0.2 依赖铁律

* 本skill不知道任何项目的存在。项目专属内容只能以输入（项目brief、定位声明）或本skill产出文档的形式存在于项目侧。
* 不假设任何上下游skill存在。若环境中有套件skill，标准协作：人物两清单 → 角色设计；节拍表 → 色彩剧本 / editorial / 分镜；价值主张 → 总导演。
* 按需取用：用户只要logline就走到第2步，只要诊断就走诊断模式。但凡涉及好坏判断，定位声明不可省。

### 0.3 元规则（系统自我修正）

遇到评价体系解释不了的公认好故事：不打补丁，先问「哪个二元判断其实是被压扁的轴」，升维处理。（先例：抓力门槛→吸引力轴；余味有无→确认↔重组光谱。）

### 0.4 输出纪律

结论先行，短句直说，不堆术语，不绕。诊断输出按「影响大小 × 修复成本」排序，每个问题给位置、病因、修法。

## 一、评价体系（速查版，详解见 references/01-coordinate-system.md）

### 1.1 三门槛——坏一条，全盘不合格

门槛只有合格与缺陷，没有高分。轴是调配比的，门槛是修缺陷的。

| 门槛      | 标准                 | 合格线                             | 典型崩法         |
| ------- | ------------------ | ------------------------------- | ------------ |
| **完整**  | 挖的坑都有回应            | 回应 \= 回答 / 明确不答 / 转化为新问题。开放结局合格 | 烂尾：坑被遗忘      |
| **自洽**  | 守自己立的规矩            | 世界规则 / 人物性格 / 因果三层自洽。不要求写实      | 机械降神；人物OOC   |
| **可追随** | 观众随时能答：谁、要什么、发生了什么 | 能重建即可，不要求容易                     | 动机不明；时空乱跳无锚点 |

### 1.2 四轴——好故事同时做到四件事

| 轴       | 观众端效应           | 刻度                 | 供能来源                       |
| ------- | --------------- | ------------------ | -------------------------- |
| **吸引力** | 想一直看下去          | 五通道各自强度            | 问题 / 世界 / 人物魅力 / 概念 / 类型承诺 |
| **在乎**  | 在乎故事里的人         | 深度 × 广度 × 指向       | 六机制（references/02）         |
| **情绪**  | 真的笑 / 哭 / 爽 / 怕 | 类型 × 强度 × 丰富度 × 节奏 | 四来源按深浅：在乎 > 谜题 > 奇观 > 直接刺激 |
| **意义**  | 看完带走东西          | 清晰度 × 确认↔重组 × 半衰期  | 价值主张 + 情绪积累                |

**依赖关系（不是时间先后）**：吸引力从第一秒到最后一秒都得在线；情绪的强度受限于事件发生前已建立的在乎；意义靠情绪积累成立——被体验的才算，被告知的是说教。

**四种衔接故障**：

1. 类型承诺没兑现（吸引力开的票，情绪轴拒付）
2. 没建立在乎就煽情（尬煽、奇观疲劳）
3. 有情绪没沉淀（好看但空）
4. 有主张没情绪（说教）

## 二、生成工序（七步）

### 第0步 定位声明

开工前先填。没有定位声明不准动笔，也不准评价。

形态/时长：（长片 / 剧集×集数 / 短片 / 微短剧 / 游戏叙事 / ...） 受众： 类型承诺：（观众来看什么：爽 / 哭 / 笑 / 怕 / 解谜 / 奇观 / 陪伴 / ...） 四轴配比：（四条轴各标 高/中/低，指明主轴；配比无对错，只有是否兑现） 对标作品：（2-3部，可选）

### 第1步 核心三件

* **概念**：what if 一句话。检验：这个设定本身有没有人想看？
* **渴望**：谁、拼命想要什么、为什么现在必须要。检验：够具体吗？有期限吗？
* **价值主张**：故事想论证什么。走确认（让观众更信他已信的）还是重组（让观众换个角度看世界）。

三件分别是吸引力、在乎、意义的种子。**至少一件必须强。** 三件都平庸，回炉，不进下一步。

### 第2步 Logline

主角 + 处境 + 目标 + 障碍 + 钩子，一句话。

自检三问：渴望具体吗；障碍比主角强吗；钩子挂在吸引力哪条通道上。30秒讲不清就回炉。

### 第3步 人物配置

* 主角两张清单分开填（机制详见 references/02）：
  * **为什么想看他**：魅力五机制（矛盾同体 / 某维拉满 / 猜不到但事后合理 / 说做风格化 / 替观众越界）选2-3条，写出具体落点
  * **为什么心疼他**：在乎六机制（渴望 / 亏欠 / 缺口 / 投入 / 连带 / 代入）选2-3条，写出具体落点
* 反派至少配魅力。只有功能没有魅力的反派撑不起对抗。
* 每个配角写一句存在理由，写不出就删。
* 产出「人物两清单」，这是给角色设计skill的接口。

### 第4步 节拍表

节拍表回答五件事：什么时候发生什么事，动用观众对谁的在乎，触发什么情绪，开了什么坑，还了什么坑。

| # | 节拍 | 事件（谁做了什么） | 动用的在乎 | 情绪（类型/强度1-5/来源） | 坑（开/还/转） |
| - | -- | --------- | ----- | --------------- | -------- |

结构脚手架按定位从锚点库选（references/03）。**锚点是脚手架，不是标准答案**——节拍表填完用四轴检验，不用模板检验。

整表四查：

1. 情绪曲线有形状：最高峰在结尾前；中段有起伏，不能平
2. 丰富度对照定位：合家欢palette要宽，类型片允许窄而深
3. 每个坑都有归宿（对照门槛·完整）
4. 意义是被事件演出来的，不是被台词说出来的

### 第5步 Treatment（到此为止，剧本交 screenwriter）

按节拍表展开成 treatment：散文、现在时、到场不到镜头，把每场的事件、情绪、转折讲清楚。这是本skill的终点产物。

**剧本（场景/动作/对白）由 screenwriter 接手**——它负责把 treatment 写成有潜台词的对白、晚进早出的场景、可视化的动作。本skill不写剧本，但要把"主题靠体验不靠台词说"这条意义轴纪律传递给它（见第六章意义轴）。

### 第6步 自审（循环4-6步，直到通过）

按 references/04 清单走：门槛 → 轴 → 衔接 → 配比对照定位声明。

通过标准：三门槛零缺陷；主轴达到定位声明的目标值；四种衔接故障一个都没有。

## 三、诊断模式（用户拿现成故事来）

输入可以是任何颗粒度：一句梗概、大纲、节拍表、完整剧本、成片描述。

流程固定五步：

1. **先问定位**。用户没给就先问形态、受众、类型承诺。没有定位不评好坏。
2. **三门槛扫描**：不完整 / 不自洽 / 跟不上。有门槛缺陷先报告并停在这里——门槛没修好，谈轴没有意义。
3. **四轴逐条**：每条轴给状态（强/正常/亏）+ 证据（指向具体位置）。
4. **衔接四查**：承诺兑现 / 在乎先于煽情 / 情绪有沉淀 / 主张有体验。
5. **输出**：问题按「影响大小 × 修复成本」排序。每个问题三件套：位置（哪场/哪个节拍）、病因（哪条轴/门槛，哪个来源断了）、修法（具体建议，不止说"加强"）。

常见病症对照表见 references/04-diagnostic-checklist.md。

## 四、自审规则（评审纪律）

* 对片不对人。只指出问题，修法给建议，最终决定权在用户。
* 诊断顺序铁律：先门槛，再轴，再衔接。门槛坏了不谈轴。
* 不拿单一模板当裁判（"不符合Save the Cat"不是问题，"中段没有情绪起伏"才是问题）。
* 遇到模型外的反例，走0.3元规则升维，不硬套。

## 五、输出接口（字段进套件数据schema）

| 产物      | 字段                           | 下游                |
| ------- | ---------------------------- | ----------------- |
| 定位声明    | 形态/时长/受众/类型承诺/四轴配比/对标        | 全套件               |
| Logline | 一句话（主角+处境+目标+障碍+钩子）          | 总导演               |
| 人物两清单   | 每角色：功能/渴望/魅力机制×n/在乎机制×n/缺口   | 角色设计              |
| 节拍表     | 节拍/事件/在乎/情绪（类型·强度·来源）/坑      | 色彩剧本、editorial、分镜 |
| 价值主张    | 一句话 + 确认/重组 + 论证线（哪几个节拍完成论证） | 总导演               |

## 六、反模式（永远不做）

1. 没有定位声明就动笔或评价
2. 拿模板当答案——锚点是脚手架，四轴才是裁判
3. 主角没有具体渴望就往下写
4. 没建立在乎就堆大事件
5. 用台词说主题
6. 坑开了不管
7. 第三幕冒出没铺垫的能力救场
8. 把「我想表达」凌驾于「观众能体验」
9. 诊断时绕过门槛直接谈轴
10. 输出绕弯卖弄——结论直说
